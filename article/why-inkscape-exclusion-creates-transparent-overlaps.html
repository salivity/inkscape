Why Inkscape Exclusion Creates Transparent Overlaps

This article explains why the Exclusion operation in Inkscape produces transparent overlapping zones in self-intersecting paths. It breaks down the mathematical logic behind Boolean operations, details how SVG fill rules—specifically the Even-Odd rule—dictate transparency, and provides straightforward solutions to control or reverse this behavior in your vector artwork.

Boolean Exclusion Logic

The Exclusion operation in Inkscape (Path > Exclusion or Ctrl + ^) is a Boolean XOR (exclusive OR) operation. In set theory, the symmetric difference between two shapes \(A\) and \(B\) is defined as \((A \cup B) \setminus (A \cap B)\).

When two shapes overlap, any area shared by an even number of shapes is excluded from the final shape. When applied to self-intersecting paths, Inkscape treats the self-overlapping sections as intersecting sub-paths, causing the overlapping segments to cancel each other out and render as empty space.

The Role of Fill Rules

The visual appearance of self-intersecting paths in SVG and Inkscape is fundamentally determined by the path's fill rule. When an Exclusion operation is executed, Inkscape typically applies the Even-Odd fill rule to the resulting path.

  1. Even-Odd Rule: To determine whether any given point lies inside or outside the shape, the rendering engine draws an imaginary ray from that point outward to infinity and counts how many path segments it crosses.

    • If the ray crosses an odd number of path boundaries, the area is considered inside and is filled with color.
    • If the ray crosses an even number of path boundaries, the area is considered outside and remains transparent.
    • In a self-intersecting path, an overlapping zone is enclosed by multiple boundaries. A ray cast from the center of this overlap crosses at least two path segments (an even number), marking that zone as "outside" and making it transparent.

  2. Non-Zero Winding Rule: By contrast, the Non-Zero rule tracks the direction (winding) of the path segments. If path segments loop in the same direction, overlapping areas remain filled. When the Exclusion operation combines paths, it overrides this winding behavior by restructuring the path geometry to follow the XOR logic, forcing overlapping regions to behave according to Even-Odd principles.

How to Prevent or Fix Transparent Overlaps

If transparent overlapping zones are undesirable in your design, use the following methods to resolve them:

  • Switch the Fill Rule: Select the object, open the Fill and Stroke dialog (Shift + Ctrl + F), go to the Fill tab, and locate the fill rule icons in the bottom-right corner. Switch from Even-Odd to Non-Zero to see if the overlapping areas refill.
  • Use Union Instead of Exclusion: If you want self-intersecting paths or overlapping shapes to merge into a single solid silhouette without cutouts, select the paths and choose Path > Union (Ctrl + +).
  • Break Apart and Recombine: If an existing path has unwanted transparent holes caused by an exclusion, choose Path > Break Apart (Shift + Ctrl + K) to separate the outer boundaries and inner cutouts into distinct objects, then apply Path > Union to merge them back into a single solid shape.
