How 2Geom Handles Boolean Clipping in Inkscape

This article provides an overview of how the 2Geom C++ geometry library processes Boolean clipping operations within Inkscape. It details the underlying algorithmic pipeline, tracing the process from path representation and curve intersection detection to planar graph construction, winding number evaluation, and final path reconstruction.

Path Representation and Pre-Processing

2Geom represents vector shapes as collections of paths and path vectors (Geom::Path and Geom::PathVector). These paths consist of contiguous parametric curve fragments, primarily cubic and quadratic Bézier segments, circular arcs, and linear segments.

Before computing a Boolean clip, 2Geom prepares the operands by standardizing their representations. The curves are analyzed and partitioned into monotonic segments along the coordinate axes. Monotonic decomposition ensures that each sub-segment varies strictly in one direction, which simplifies subsequent spatial sorting and intersection tests.

Intersection Detection and Curve Splitting

The Boolean engine identifies all points where the clipping path intersects the subject path:

  1. Bounding Box Filtering: 2Geom uses axis-aligned bounding boxes (AABBs) organized into hierarchical spatial trees. This quickly discards pairs of curve segments that cannot possibly intersect.
  2. Numerical Intersection Solving: For segments with overlapping bounds, 2Geom finds exact intersection coordinates using Bézier clipping algorithms and iterative root-finding techniques (such as Newton-Raphson or polynomial root solvers).
  3. Subdivision: Once the intersection points (parameter values \(t\)) are identified, the curves of both shapes are split at these exact coordinates. This converts both paths into a collection of smaller segments that touch only at their endpoints.

Planar Graph Construction

After splitting the curves, 2Geom constructs an arrangement or planar graph. In this internal data structure:

  • Vertices represent the intersection points and original path endpoints.
  • Edges represent the subdivided directed curve segments linking these vertices.
  • Faces represent the bounded and unbounded regions of the 2D plane enclosed by the edges.

Each directed edge maintains topological links to its twin (the same segment traversed in the opposite direction) and its adjacent faces, allowing the engine to traverse boundaries systematically.

Winding Number and Inside/Outside Classification

To determine which portions of the paths belong in the clipped result, 2Geom calculates winding numbers for the regions formed by the graph:

  • The engine evaluates how many times a path wraps around any given region, supporting both the non-zero and even-odd fill rules specified by the SVG standard.
  • Each edge is classified based on the winding state of the regions immediately to its left and right relative to both the subject and clipping paths.
  • For a standard Boolean clip (intersection), only edges that lie along the boundary between an "inside" region (where both the subject and the clipping path meet their fill criteria) and an "outside" region are retained.

Edge Traversal and Path Reconstruction

Once the valid boundary edges are tagged, 2Geom reassembles them into closed vector loops:

  1. Edge Chaining: The algorithm selects an unused valid edge and follows it to its target vertex, selecting the next outgoing valid edge based on angular sorting around the vertex to preserve correct winding orientation.
  2. Degeneracy Handling: Micro-segments, self-intersecting loops, and coincident overlapping edges are resolved or pruned to prevent numerical instabilities or malformed paths.
  3. Path Generation: The assembled chains of curve fragments are converted back into native Geom::Path objects, resulting in clean, closed SVG path data that Inkscape displays as the final clipped vector shape.
