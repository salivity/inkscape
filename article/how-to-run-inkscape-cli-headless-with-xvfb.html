How to Run Inkscape CLI Headless with Xvfb

Running Inkscape in a headless Linux environment can trigger display-related errors because its underlying GTK libraries often expect an active X11 graphical display server. This article demonstrates how to bypass this limitation by using Xvfb (X Virtual Framebuffer), a lightweight utility that mimics an X11 server entirely in memory. Following this guide, you will learn how to install Xvfb, execute one-off Inkscape commands using xvfb-run, and manage a persistent virtual display for batch processing and automated pipelines.

1. Install Required Packages

First, ensure both Inkscape and the Xvfb package are installed on your headless server.

For Debian/Ubuntu systems:

sudo apt update
sudo apt install -y inkscape xvfb

For RHEL/CentOS/Fedora systems:

sudo dnf install -y inkscape xorg-x11-server-Xvfb

2. Method 1: Execute Using xvfb-run (Recommended)

The most direct approach for running isolated commands or integration within CI/CD scripts is xvfb-run. This wrapper automatically starts a virtual X server, allocates an unused display number, executes the specified command, and cleanly terminates the virtual server when finished.

To convert an SVG to a PNG:

xvfb-run --auto-servernum --server-args="-screen 0 1024x768x24" inkscape input.svg -o output.png

To export an SVG to PDF:

xvfb-run --auto-servernum inkscape input.svg --export-filename=output.pdf

Key arguments explained:

  • --auto-servernum: Automatically finds an available display number to prevent collisions with existing services.
  • --server-args="-screen 0 1024x768x24": Specifies the virtual screen dimensions and 24-bit color depth, avoiding rendering glitches.

3. Method 2: Use a Dedicated Persistent Xvfb Process

If you are running batch conversions or loops inside a script, spinning up and tearing down an Xvfb instance for every command creates unnecessary overhead. Instead, launch a single Xvfb instance in the background for the duration of the tasks.

  1. Start Xvfb on display :99:
Xvfb :99 -screen 0 1024x768x24 -nolisten tcp &
XVFB_PID=$!
  1. Export the DISPLAY environment variable so Inkscape directs output to the virtual display:
export DISPLAY=:99
  1. Run your Inkscape commands normally:
inkscape drawing1.svg -o drawing1.png
inkscape drawing2.svg -o drawing2.pdf
  1. Terminate the background Xvfb process once tasks are complete:
kill $XVFB_PID

Headless Server Considerations

  • Missing Fonts: Headless servers often lack standard system fonts, causing text in SVGs to render as fallback glyphs or default sans-serif fonts. Ensure core font packages are installed: 
    sudo apt install -y fonts-dejavu fonts-liberation
  • DBus Warnings: You may see warnings regarding the session bus. In most rendering pipelines, these can be safely ignored, or wrapped with dbus-run-session if required: 
    xvfb-run dbus-run-session inkscape input.svg -o output.png
