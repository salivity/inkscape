Inkscape 90 to 96 DPI Transition: Scaling Impact

The release of Inkscape 0.92 marked a major architectural shift by changing the software's default internal resolution from 90 DPI to 96 DPI. This article examines why this change occurred, how it directly affected the visual and physical scaling of legacy documents, and the solutions Inkscape implemented to manage the resulting size discrepancies across different graphic workflows.

The Reason for the Change

Prior to version 0.92, Inkscape used an internal standard of 90 dots per inch (DPI) to map user units (pixels) to physical measurements like inches and millimeters. However, the World Wide Web Consortium (W3C) standardized the CSS and SVG specifications at 96 DPI (where 1 inch equals 96 CSS pixels).

This discrepancy meant that an SVG created in older versions of Inkscape would render at a different size when opened in modern web browsers or other vector editing software, such as Adobe Illustrator. To align with modern web and SVG standards, Inkscape shifted its baseline to 96 DPI in version 0.92.

Direct Impact on Legacy Documents

When files created in Inkscape 0.91 or earlier were opened in Inkscape 0.92 without modification, their visual scale changed by a factor of 96/90 (approximately 1.0667, or a 6.67% difference). The specific impact depended on how the original SVG defined its units:

  • Pixel-Based Documents: Elements defined purely in user units or pixels (px) maintained their pixel dimensions, but appeared roughly 6.67% smaller when printed or translated into real-world physical units (inches, centimeters, millimeters).
  • Physical-Unit Documents: Files designed with absolute real-world units (such as a 100 mm box for laser cutting or print design) retained their exact real-world dimensions on paper or output, but expanded by 6.67% in pixel count. This expansion frequently caused designs to clip outside the document's original viewBox or canvas boundaries.
  • Text and Line Widths: Because font sizes and stroke widths in older files were often defined in user units, text spacing, kerning, and line weights were noticeably altered relative to adjacent elements defined in physical units.

Inkscape’s Migration Solutions

To prevent existing artwork from breaking, Inkscape 0.92 introduced an automatic migration dialog that appeared whenever a user opened a legacy file lacking an explicit 96 DPI identifier. Users were presented with several options:

  1. Scale Document Elements: Inkscape physically scaled the elements inside the document by 96/90 to preserve their intended real-world dimensions relative to the page.
  2. Adjust the viewBox: The software modified the SVG's root viewBox coordinates. This preserved the visual appearance and relative proportions of the document without altering the underlying coordinate numbers of the drawn paths.
  3. Leave Unchanged: Advanced users could bypass automatic conversion and adjust scale properties manually using the Document Properties dialog or XML editor.

Long-Term Impact

While the transition caused temporary disruption for projects requiring precise physical tolerances—such as CNC machining, plotter design, and technical drawings—it resolved longstanding interoperability issues. Modern SVGs exported from Inkscape now match the rendering scale of modern web browsers, rendering engines, and third-party vector tools consistently without requiring manual scaling compensation.
