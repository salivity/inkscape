Inkscape Weblate Translation Guidelines

This guide provides an overview of the essential rules, technical requirements, and quality standards volunteer translators must follow when localizing Inkscape strings on the Weblate platform. Translating Inkscape requires more than linguistic fluency; it demands strict adherence to software-specific syntax, interface layout considerations, established glossaries, and community coordination to ensure a cohesive user experience across all supported languages.

1. Preserve Variables, Placeholders, and Code Syntax

Inkscape uses various placeholders and format specifiers to insert dynamic content at runtime. Translators must never translate, modify, or remove these elements:

  • Format Specifiers: Keep tokens like %s, %d, %1$s, or {0} exactly as they appear in the source text. Rearranging their order is permissible only when supported by indexed specifiers (e.g., %1$s and %2$s) to match target language grammar.
  • Markup and HTML/XML Tags: Preserve tags such as <b>, </b>, <i>, or <filename> unchanged.
  • Escape Characters: Maintain special characters such as \n (newline) and \t (tab) precisely where required.

2. Manage Access Keys and Accelerators

Inkscape’s user interface relies on access keys (keyboard mnemonics) for menu navigation, denoted by an underscore (_) directly preceding the designated letter:

  • Include the Accelerator: If the source string contains an underscore (e.g., _File), the translated string must also contain an underscore (e.g., _Datei in German).
  • Avoid Collisions: Ensure that two items within the same menu or dialogue do not share the same access key letter.
  • Non-Latin Scripts: For languages that do not use Latin scripts, it is customary to append the Latin accelerator in parentheses at the end of the label, such as Файл (_F).

3. Maintain Consistent Terminology

Inkscape features specialized tools and concepts unique to vector graphics. Translators must:

  • Consult the Glossary: Utilize the glossary feature directly integrated into the Weblate interface to maintain uniform terminology (such as "Path", "Node", "Canvas", "Stroke", and "Fill").
  • Align with the Operating System: When translating standard UI elements (e.g., "Preferences", "Save As", "Cancel"), follow the standard conventions of mainstream desktop environments (GNOME, macOS, Windows) for the target language.

4. Respect Punctuation and Typographical Conventions

Do not automatically mirror English typography if it violates the standard rules of the target locale:

  • Ellipses: Use the proper ellipsis character (…) or three dots (...) exactly as indicated by the source string. An ellipsis in UI items generally indicates that a dialogue will open.
  • Quotation Marks: Convert straight quotes ("") into locale-appropriate quotation marks (such as « » in French or „ “ in German) unless the string represents raw code, regular expressions, or attribute values.
  • Spacing: Observe rules regarding non-breaking spaces before punctuation marks (e.g., before colons or semicolons in French).

5. Handle Plural Forms Correctly

When localizing strings with variable counts, Weblate presents gettext plural forms specific to your language:

  • Provide appropriate translations for every grammatical plural category required by the target language (e.g., One, Few, Many, Other).
  • Do not assume a singular/plural binary if your language uses a different numbering system.

6. Resolve Weblate Quality Checks and Warnings

Weblate runs automated validation checks on every submitted string. Translators must:

  • Review and resolve red and orange check alerts before marking strings as completed.
  • Correct common errors flagged by the system, such as missing trailing spaces, mismatched trailing colons, or unescaped characters.
  • If a warning is a false positive due to target language grammatical rules, use the "Ignore" option rather than forcing an incorrect translation.

7. Avoid Unedited Machine Translation

While Weblate provides machine translation suggestions:

  • Submitting raw, unedited machine-generated translations is strictly prohibited.
  • Always review, adapt, and refine automated suggestions to ensure natural syntax, context accuracy, and proper technical phrasing.

8. Communicate with Language Teams and Developers

  • String Comments: Use Weblate’s built-in comment system to ask questions about context, report ambiguities, or notify developers of typos in the English source text.
  • Language Coordinators: Defer to existing language team leads for established language-specific style guides and conventions.
