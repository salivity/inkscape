Group Inkscape Python Extensions into Single Undo

This article explains how to ensure an entire Inkscape Python extension run registers as a single entry in Inkscape's undo history. By understanding the data flow between Inkscape and its Python extension subsystem (inkex), structuring your script using inkex.EffectExtension, and properly setting metadata in your extension definition file, you can manipulate complex vector data while providing a clean, single-step undo experience for end users.

How Inkscape Tracks Extension Changes

Inkscape isolates external Python extensions from its live internal memory. When an extension is triggered from the menu, Inkscape creates a single transaction boundary in its undo stack:

  1. Inkscape writes the current document state as an XML stream to standard input (stdin).
  2. The Python script parses the document, performs all node manipulations in memory, and writes the modified XML back to standard output (stdout).
  3. Inkscape compares or replaces the document tree with the returned data and commits the entire batch of changes as one atomic undo step.

Because the live canvas is updated only after the script exits, all standard DOM alterations made during a single execution naturally collapse into one undo event.

Standard Implementation with inkex.EffectExtension

To take advantage of atomic undo grouping, always base your extension on inkex.EffectExtension rather than invoking external Inkscape shell commands. Perform all operations within the overridden effect() method.

import inkex
from inkex import Circle

class MyBatchExtension(inkex.EffectExtension):
    def effect(self):
        # All modifications happen in-memory on self.svg
        for element in self.svg.selection:
            # Example operation: add a circle at element coordinates
            bbox = element.bounding_box()
            if bbox:
                circle = Circle(cx=str(bbox.center.x), cy=str(bbox.center.y), r="5")
                circle.style = {'fill': 'red', 'stroke': 'none'}
                self.svg.append(circle)

if __name__ == '__main__':
    MyBatchExtension().run()

As long as modifications are applied to self.svg and standard output is preserved for the main process exit, Inkscape records the run as a single action.

Avoiding Fractured Undo Histories

The most common reason an extension splits into multiple undo operations—or fails to integrate into the undo stack properly—is the misuse of interactive commands or external subprocess calls.

  • Do not invoke multiple Inkscape CLI actions: Using inkex.command.inkscape() to execute multiple batch actions (such as verb-call or --actions) against an active GUI document bypasses the standard input/output pipeline and creates separate undo steps for each action call.
  • Keep processing within the DOM: If you must use path operations (such as unions or intersections) that standard XML parsing cannot perform, compute them via path libraries like shapely or pass chained action strings in a single call rather than executing sequential isolated commands.

Naming the Undo Step in the .inx File

Inkscape labels the single undo entry based on the <name> tag defined inside the extension's corresponding .inx file:

<?xml version="1.0" encoding="UTF-8"?>
<inkscape-extension xmlns="http://www.inkscape.org/namespace/inkscape/extension">
    <name>Batch Shape Generator</name>
    <id>org.example.batch_shape_generator</id>
    <effect>
        <object-type>all</object-type>
        <effects-menu>
            <submenu name="Custom Tools"/>
        </effects-menu>
    </effect>
    <script>
        <command location="inx" interpreter="python">my_script.py</command>
    </script>
</inkscape-extension>

When a user runs this extension, the entry appearing under Edit > Undo will read Undo: Batch Shape Generator, reverting all generated nodes and modifications in one step.
