How to Write Inkscape Documentation and Tutorials

Contributing to the official Inkscape documentation and tutorials is a structured process that helps millions of users master open-source vector graphics. This guide outlines the essential steps for getting involved, understanding the technical toolset, adhering to Inkscape's writing and style guidelines, and submitting your contributions directly to the Inkscape Docs team via GitLab.

1. Join the Inkscape Documentation Community

Before writing, connect with the Inkscape Documentation Team to coordinate efforts, avoid duplicated work, and find active documentation priorities:

  • Inkscape GitLab: Create an account on the Inkscape GitLab instance (gitlab.com/inkscape), where all documentation code, issue tracking, and merge requests are managed.
  • Communication Channels: Join the Inkscape Docs mailing list or the documentation channel on Inkscape's Rocket.Chat or Matrix networks to introduce yourself and discuss topics you wish to cover.
  • Check Open Issues: Review the documentation issue tracker to find missing features, outdated guides, or reported errors that need attention.

2. Set Up the Documentation Toolchain

Inkscape's official manual and guides are built primarily using Sphinx and reStructuredText (rST):

  1. Fork and Clone the Repository: Fork the inkscape-docs/manuals repository on GitLab to your personal account and clone it locally.
  2. Install Dependencies: Install Python along with Sphinx and any required extensions listed in the repository's requirements.txt file.
  3. Build Locally: Run the local build command (typically make html) to render the documentation into HTML, allowing you to preview your changes in a browser before submitting them.

3. Follow Inkscape Style Guidelines

Maintaining consistency across all official materials requires following established editorial and formatting standards:

  • Clear and Accessible Language: Use active voice, direct phrasing, and present tense. Write for an international audience with varying levels of English proficiency.
  • Consistent UI Terminology: Match the exact names of tools, menus, dialogs, and keybindings as they appear in the latest stable version of Inkscape (e.g., use Path > Union, not "Combine paths").
  • Formatting Conventions: Use standard rST semantic markup for user interface elements, keyboard shortcuts, and code blocks.
  • Neutral, Modular Content: Keep tutorials focused on specific workflows or tools rather than overly personal art styles.

4. Structure an Official Tutorial

Official tutorials should be practical, reproducible, and easy to follow:

  1. Introduction: State the goal of the tutorial, the tools covered, and the expected final result.
  2. Prerequisites: List required software versions, basic skills needed, or sample files.
  3. Step-by-Step Instructions: Break the process down into numbered, logical steps. Keep paragraphs short and provide context for why a specific tool or setting is used.
  4. Conclusion: Summarize what was learned and suggest next steps or related tools to explore.

5. Submit Your Work via Merge Request

Once your writing is complete and builds without errors locally:

  1. Create a Feature Branch: Branch off the main development branch with a descriptive name (e.g., update-node-tool-guide).
  2. Commit Changes: Write clear, concise Git commit messages explaining what was added or modified.
  3. Open a Merge Request (MR): Push your branch to your GitLab fork and open an MR against the main Inkscape documentation repository.
  4. Engage with the Review: The documentation maintainers will review your submission, suggest improvements, and verify technical accuracy before merging. Once merged, the content is automatically queued for translation through Weblate and published to the official Inkscape website.
