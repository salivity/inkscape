Test Inkscape SVG Rendering with GitHub Actions

Automating the testing of SVG rendering ensures that vector assets remain visually consistent and free of corruption across different revisions. This guide demonstrates how to configure a GitHub Actions CI/CD workflow that installs Inkscape in a headless Linux environment, exports SVGs to raster images, and compares the rendered outputs against approved baseline references to detect visual regressions.

Prerequisites and Repository Structure

To implement automated visual regression testing for your SVGs, organize your repository with designated directories for source files and baseline renders:

.
├── .github/
│   └── workflows/
│       └── svg-render-test.yml
├── assets/
│   └── logo.svg
└── tests/
    └── baselines/
        └── logo.png
  • assets/: Contains the production SVG files.
  • tests/baselines/: Contains reference PNGs previously verified for correct rendering.

Creating the GitHub Actions Workflow

Create a new file at .github/workflows/svg-render-test.yml. This configuration runs on Ubuntu, installs Inkscape and ImageMagick, converts the target SVGs into PNGs, and checks for pixel discrepancies.

name: Test Inkscape SVG Rendering

on:
  push:
    branches: [ main ]
    paths:
      - 'assets/**.svg'
      - '.github/workflows/svg-render-test.yml'
  pull_request:
    branches: [ main ]
    paths:
      - 'assets/**.svg'

jobs:
  render-and-test:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Install Inkscape and ImageMagick
        run: |
          sudo apt-get update
          sudo apt-get install -y inkscape imagemagick

      - name: Create output directory
        run: mkdir -p build/renders build/diffs

      - name: Render SVGs with Inkscape CLI
        run: |
          for file in assets/*.svg; do
            filename=$(basename "$file" .svg)
            echo "Rendering $filename.svg..."
            inkscape "$file" \
              --export-filename="build/renders/$filename.png" \
              --export-dpi=96
          done

      - name: Compare renders against baselines
        run: |
          FAILED=0
          for baseline in tests/baselines/*.png; do
            filename=$(basename "$baseline" .png)
            render="build/renders/$filename.png"
            diff="build/diffs/$filename-diff.png"

            if [ ! -f "$render" ]; then
              echo "Error: Rendered file $render does not exist."
              FAILED=1
              continue
            fi

            # Compare images and calculate pixel difference
            # ImageMagick's compare outputs difference metric to stderr
            DIFFERENCE=$(compare -metric AE "$baseline" "$render" "$diff" 2>&1 || true)

            if [ "$DIFFERENCE" -ne 0 ]; then
              echo "FAIL: $filename.png differs by $DIFFERENCE pixels."
              FAILED=1
            else
              echo "PASS: $filename.png matches baseline."
              rm "$diff"
            fi
          done

          if [ "$FAILED" -ne 0 ]; then
            echo "SVG rendering tests failed."
            exit 1
          fi

      - name: Upload failed diff artifacts
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: visual-diff-results
          path: |
            build/renders/
            build/diffs/

How the Pipeline Works

1. Dependency Installation

The job uses apt-get on Ubuntu to install inkscape for headless rendering and imagemagick for automated image comparison.

2. Inkscape Command Line Execution

Inkscape 1.0+ includes native CLI support. The command:

inkscape input.svg --export-filename=output.png --export-dpi=96

executes the rendering engine headlessly, exporting the graphic to raster format at the specified DPI without opening a graphical display server.

3. Visual Regression Comparison

The ImageMagick compare utility inspects the generated PNG against the reference PNG located in tests/baselines/. Using -metric AE (Absolute Error), it counts the number of distinct pixels between the two files:

  • An output of 0 indicates an identical render.
  • Any value greater than 0 indicates a visual regression or deviation. When this occurs, a visual diff image highlighting the changed pixels in red is generated inside build/diffs/.

4. Failure Handling

If any file deviates from its baseline:

  • The script sets an exit code of 1, marking the GitHub Action check as failed.
  • The upload-artifact step triggers conditionally on failure, preserving both the rendered files and visual diff images so developers can download and inspect the discrepancies directly from the pull request interface.
