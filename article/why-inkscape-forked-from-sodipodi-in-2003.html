Why Inkscape Forked From Sodipodi in 2003

In 2003, developers Bryce Harrington, MenTaLguY, Nathan Hurst, and Ted Gould broke away from the Sodipodi vector editor to create Inkscape. This fork was triggered by fundamental architectural disagreements regarding standard SVG compliance, software language and design paradigms, desktop interface standards, and project governance. While Sodipodi aimed to be a general vector drawing tool with its own conventions, the Inkscape founders sought to build a strictly compliant, modern W3C Scalable Vector Graphics (SVG) editor with an open, community-driven development model.

Strict SVG Compliance vs. Arbitrary Storage

The primary technical divide centered on how the software handled the SVG format. Sodipodi used SVG primarily as a storage file format rather than an internal design specification. It introduced custom namespaces, non-standard conventions, and discarded or modified unsupported SVG elements upon saving.

The Inkscape founders argued that SVG should serve as the software's native, fully compliant internal representation. They wanted the editor to strictly adhere to W3C SVG standards, ensuring that valid SVG files could be loaded, edited, and saved without loss of syntax, unsupported metadata, or arbitrary code mutation.

Modernizing the Codebase: C to C++

Sodipodi was written in procedural C using GTK+ and custom object hierarchies inspired by early GtkObject implementations. The codebase suffered from high coupling, making it difficult to introduce new features without destabilizing existing subsystems.

The forking developers wanted to transition the codebase to C++ and utilize modern object-oriented programming paradigms. By moving to C++ and adopting the gtkmm C++ wrapper for GTK, the Inkscape team aimed to improve code modularity, memory management, and maintainability. Sodipodi’s lead maintainer, Lauris Kaplinski, strongly favored maintaining the pure C codebase, creating an impasse over code modernization.

User Interface and Desktop Integration

Sodipodi utilized a multi-window, floating-palette interface similar to the original design of the GIMP. Toolbars, palettes, and document canvases were separated into detached floating windows, which created window-management clutter on standard desktops.

Inkscape’s creators wanted to modernize the user experience by moving to a streamlined, single-window editing environment. Furthermore, they committed to following the GNOME Human Interface Guidelines (HIG), focusing on keyboard accessibility, standardized menu structures, and direct on-canvas tool controls to make vector illustration intuitive for a broader audience.

Governance and Community Structure

Beyond code architecture, the developers clashed over project management. Sodipodi operated under a centralized, benevolent-dictator model, where architectural approval and code commits were heavily gatekept by a single maintainer.

The Inkscape founders favored an open, distributed governance model that lowered barriers to contribution. They established an open patch policy, an egalitarian core-team structure, and a welcoming environment for third-party contributors. This cultural shift, combined with technical modernization, immediately attracted an active contributor base that rapidly outpaced Sodipodi's original development trajectory.
