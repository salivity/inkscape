Inkscape Geometric vs Visual Bounding Box Explained

Inkscape calculates path boundaries using two distinct methods: the geometric bounding box and the visual bounding box. While the geometric calculation derives its dimensions exclusively from the mathematical coordinate extents of the path's curves, the visual calculation expands these boundaries to account for stroke thickness, join styles, cap styles, and markers. Understanding how Inkscape computes these two values is essential for precise object alignment, export sizing, and SVG layout design.

Geometric Bounding Box: Curve Extents

The geometric bounding box calculates the smallest axis-aligned rectangle (\([x_{\min}, y_{\min}]\) to \([x_{\max}, y_{\max}]\)) that completely encloses the underlying path data, treating the stroke width as zero.

To compute the extents of a path consisting of straight line segments and cubic or quadratic Bézier curves, Inkscape relies on its underlying geometry library, lib2geom:

  1. Node and Endpoint Evaluation: The coordinates of all on-path nodes (endpoints of segments) provide the initial baseline extents.
  2. Derivative Calculation for Curve Extrema: A Bézier curve often bows outward beyond the straight line connecting its endpoints. Simply using off-path control handles would overestimate the boundary. Instead, Inkscape finds the exact roots of the curve's first derivative: \[\frac{d}{dt} B(t) = 0\] Solving this equation for \(t\) (where \(0 \le t \le 1\)) reveals the parameter values where the slope along the X or Y axis is zero.
  3. Extrema Substitution: Evaluating the Bézier polynomial \(B(t)\) at these stationary points yields the exact local minima and maxima. The geometric boundary is defined by the global minimum and maximum of all segment endpoints and curve extrema combined.

Visual Bounding Box: Stroke Width and Topology

The visual bounding box expands the geometric curve extents to encompass the full rendered footprint of the path as defined by its SVG presentation attributes.

Inkscape computes the visual bounding box by factoring in several rendering properties:

  • Stroke Width: The path is expanded outward perpendicular to the curve tangent by half the stroke width (\(w/2\)) on either side.
  • Line Caps: At open path terminals, the cap style modifies the boundary:
    • Butt caps stop precisely at the end nodes perpendicular to the path direction.
    • Square caps project a rectangular area outward past the endpoint by a distance of \(w/2\).
    • Round caps append a semi-circle with radius \(w/2\) around the terminal node, expanding the bounding box in all directions around the endpoint.
  • Line Joins: At sharp corners between segments, joins dictate the visual extent:
    • Miter joins extend the outer stroke edges until they intersect. For acute angles, this point can project far beyond the geometric corner. Inkscape clamps this calculation according to the SVG stroke-miterlimit; if the ratio of miter length to stroke width exceeds the limit, it converts the join extent calculation to a bevel.
    • Round joins add circular arcs with radius \(w/2\) at the intersection.
    • Bevel joins cap the corner with a straight segment connecting the outer stroke edges.
  • Filters and Markers: The visual boundary also extends to encapsulate start, mid, and end markers (such as arrowheads) as well as blur filter margins (e.g., Gaussian blur radius expansions).

Practical Implications in Inkscape

Users can toggle between these two calculation modes under Edit > Preferences > Tools > Bounding box.

Selecting the Geometric Bounding Box ensures that object positioning coordinates and transformations correspond strictly to the SVG path definition (d attribute), preventing stroke modifications from changing an object's X/Y position. Selecting the Visual Bounding Box ensures that snapping, alignment tools, and canvas selections align with the outermost visible edges of the rendered artwork.
