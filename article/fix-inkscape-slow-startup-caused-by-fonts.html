Fix Inkscape Slow Startup Caused by Fonts

Inkscape often experiences significant launch delays when loading a large collection of system fonts. Every time the application starts without a valid font cache, it scans and parses every installed font file, which can cause loading screens to hang for several minutes. This guide explains how to eliminate these startup delays by properly generating the font cache, excluding unnecessary font directories, removing corrupt files, and managing active fonts efficiently.

Let the Font Cache Complete Its Initial Build

Inkscape relies on the Fontconfig library to index fonts. If you close Inkscape while it is freezing during startup, the cache file is never saved, forcing the program to scan every font again on the next launch.

  1. Launch Inkscape and leave the computer alone until the interface fully loads. Depending on your font count, this may take between 5 and 15 minutes.
  2. Once the application opens completely, close it normally.
  3. Reopen Inkscape. If the cache was successfully written to your disk, subsequent launches should take only a few seconds.

Manually Rebuild the Fontconfig Cache (Windows)

If Inkscape fails to save the cache automatically, you can force the underlying tool to build the cache directly.

  1. Close Inkscape completely.
  2. Navigate to your Inkscape installation directory (typically C:\Program Files\Inkscape\bin).
  3. Open Command Prompt inside this folder or open Command Prompt as Administrator and navigate to the path using: 
    cd "C:\Program Files\Inkscape\bin"
  4. Run the font cache utility: 
    fc-cache.exe -f -v
  5. Wait for the command to finish indexing all system and local fonts. Once complete, launch Inkscape.

Exclude Unnecessary Font Directories

Fontconfig scans standard system font folders as well as third-party directories created by software like Adobe Creative Cloud, Corel, or local user paths. You can edit the Fontconfig configuration to stop Inkscape from scanning these extra locations.

  1. Locate the fonts.conf file:
    • Windows: C:\Program Files\Inkscape\etc\fonts\fonts.conf
    • Linux: /etc/fonts/fonts.conf or ~/.config/fontconfig/fonts.conf
    • macOS: /Applications/Inkscape.app/Contents/Resources/etc/fonts/fonts.conf
  2. Open the file in a plain text editor with administrative privileges.
  3. Search for <dir> tags. These lines define which folders Fontconfig searches.
  4. Remove or comment out non-essential directories (such as third-party software font repositories) by wrapping them in <!-- and -->: 
    <!-- <dir>C:\Program Files\Common Files\Adobe\Fonts</dir> -->
  5. Save the file and restart Inkscape.

Remove Corrupted and Duplicate Fonts

A single damaged font file can cause Fontconfig to crash or hang indefinitely during the indexing process, preventing the cache from finalizing.

  • Windows: Open the Windows Font settings, review recently added third-party fonts, and remove non-standard or untrusted .ttf and .otf files.
  • macOS: Open Font Book, select all fonts, go to File > Validate Fonts, and remove any fonts marked with warnings or errors.
  • Linux: Run fc-cache -r in the terminal to identify problematic font files that generate parsing errors.

Use a Font Manager

Having thousands of active system fonts degrades the performance of most vector software. The most effective long-term solution is to keep your active system font count below 1,000 fonts.

  1. Install a dedicated font manager such as MainType (Windows), FontBase (Windows/macOS/Linux), or Typeface (macOS).
  2. Deactivate font families that you do not use on a daily basis.
  3. Activate project-specific fonts only when working on files that require them, then deactivate them when finished.
