Configure Inkscape Build Flags with GCC on Fedora

Compiling Inkscape from source on Fedora using the GCC compiler often requires customizing compiler optimization levels, linker parameters, and specific dependency search paths. This guide provides a direct, step-by-step approach to setting up Fedora’s build environment, setting GCC as the default toolchain, and passing custom build flags for dependencies using CMake and PkgConfig.

Step 1: Install Build Tools and Inkscape Dependencies

Fedora provides a convenient tool to install all development packages and build dependencies for Inkscape in a single step. Open a terminal and run:

sudo dnf install dnf-plugins-core
sudo dnf builddep inkscape
sudo dnf install git cmake ninja-build gcc-c++

Step 2: Clone the Inkscape Source Repository

Obtain the latest source code from the official GitLab repository, ensuring submodules are recursively pulled:

git clone --recurse-submodules https://gitlab.com/inkscape/inkscape.git
cd inkscape

Step 3: Define Dependency and Compiler Build Flags

Inkscape relies on CMake to detect libraries and configure the build tree. You can control how GCC interacts with dependencies using environment variables and CMake parameters:

  • Custom Dependency Locations (PKG_CONFIG_PATH and CMAKE_PREFIX_PATH): If you built libraries (such as Poppler, 2Geom, or GTKMM) in custom directories (e.g., /opt/custom_libs), tell CMake and PkgConfig where to find their metadata and headers:

    export PKG_CONFIG_PATH="/opt/custom_libs/lib64/pkgconfig:$PKG_CONFIG_PATH"

  • C/C++ Compiler Flags (CMAKE_CXX_FLAGS / CMAKE_C_FLAGS): Pass GCC-specific flags such as optimization levels (-O3), machine-specific instruction sets (-march=native), or custom include directories (-I):

    export CXXFLAGS="-O3 -march=native -pipe"
export CFLAGS="-O3 -march=native -pipe"

  • Linker Flags (CMAKE_EXE_LINKER_FLAGS / CMAKE_SHARED_LINKER_FLAGS): Specify custom library search paths (-L) and run-time library paths (-Wl,-rpath):

    export LDFLAGS="-L/opt/custom_libs/lib64 -Wl,-rpath,/opt/custom_libs/lib64"

Step 4: Configure the Build with CMake

Create a separate build directory and invoke CMake. Specify GCC (gcc and g++) explicitly, choose the Ninja generator for faster builds, and inject any dependency-specific overrides via -D flags:

cmake -B build -G Ninja \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DCMAKE_C_COMPILER=gcc \
  -DCMAKE_CXX_COMPILER=g++ \
  -DCMAKE_PREFIX_PATH="/opt/custom_libs" \
  -DCMAKE_CXX_FLAGS="$CXXFLAGS" \
  -DCMAKE_EXE_LINKER_FLAGS="$LDFLAGS" \
  -DCMAKE_SHARED_LINKER_FLAGS="$LDFLAGS"

To configure flags for an individual dependency managed by CMake (such as Boost or GraphicsMagick), append the respective CMake variables directly. For example:

  • -DBOOST_ROOT=/path/to/custom/boost
  • -DPOPPLER_INCLUDE_DIR=/path/to/poppler/include

Step 5: Compile and Verify

Execute the build using Ninja:

ninja -C build

To verify that your custom dependency flags were correctly applied, inspect the compiled binary dependencies:

ldd build/bin/inkscape

Finally, install the compiled binary or run it directly from the build directory:

./build/bin/inkscape
