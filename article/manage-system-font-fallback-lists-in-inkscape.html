Manage System Font Fallback Lists in Inkscape

Managing font fallback lists in an Inkscape project ensures that missing glyphs are automatically substituted by secondary typefaces instead of displaying as missing-character boxes. Because Inkscape adheres strictly to SVG and CSS specifications, fallback behavior is governed by multi-font stacks defined on text elements and resolved by your operating system's font rendering engine. This guide details how to implement font stacks in Inkscape using the built-in XML Editor, leverage generic font families, and configure system-level fallbacks to handle missing glyphs reliably.

Understanding SVG Font Stacks in Inkscape

In SVG, font definitions rely on the standard CSS font-family property. When a primary font lacks a specific character or glyph (such as a foreign script, math symbol, or emoji), the rendering engine traverses the comma-separated list of families defined in that property until it finds a font that contains the required glyph.

Inkscape's primary Text and Font tool (Ctrl + Shift + T or Text > Text and Font) primarily displays a single selected font family. To specify a complete fallback sequence, you must define an explicit font stack within the text element’s style attributes.

Method 1: Specifying Font Fallbacks via the XML Editor

The most precise way to define a custom font fallback list for any text object in Inkscape is through the built-in XML Editor.

  1. Select the text object with the Text tool or the Selection tool.
  2. Open the XML Editor by pressing Ctrl + Shift + X (or navigate to Edit > XML Editor).
  3. In the tree view, locate and select the target <svg:text> element or its child <svg:tspan> element containing the text.
  4. In the right-hand panel, find the style attribute.
  5. In the attribute value field, locate the font-family rule.
  6. Replace the single font name with a comma-separated list of fonts in order of priority. Wrap font names containing spaces in single quotes.
    • Example: font-family:'Roboto', 'Noto Sans', 'Segoe UI', sans-serif;
  7. Click the Set button to apply the changes.

If the primary font (Roboto) lacks a required glyph, Inkscape will sequentially check Noto Sans, then Segoe UI, and finally defer to the system's default sans-serif font.

Method 2: Defining Global Fallbacks in the SVG Style Element

To apply a universal fallback list across all text objects in a document without editing each node individually, declare a global CSS rule in the document's <svg:style> element.

  1. Open the XML Editor (Ctrl + Shift + X).
  2. Select the root <svg:svg> element.
  3. Click the New element node button at the top of the panel and enter svg:style.
  4. Select the newly created <svg:style> node, create a new attribute named type, and set its value to text/css.
  5. Add a text child node containing your default font rule: 
    text {
    font-family: 'MyPrimaryFont', 'Noto Sans', sans-serif;
}
  6. Ensure that individual text elements do not override this rule with inline styles, or remove the font-family property from the inline style attribute of specific text objects to allow them to inherit the global stack.

Method 3: Utilizing Generic Fallback Families

Always terminate your font stacks with a CSS generic family name. Generic families inform the host operating system's text renderer which typeface category to use if none of the named fonts are installed or contain the necessary glyph:

  • sans-serif: Clean, unadorned typefaces (e.g., Arial, Helvetica, DejaVu Sans).
  • serif: Typefaces with decorative strokes (e.g., Times New Roman, Georgia, DejaVu Serif).
  • monospace: Fixed-width typefaces suitable for code or alignment (e.g., Courier New, Consolas).
  • system-ui: The native operating system user interface font.

System-Level Fallback Resolution (Fontconfig and OS Handlers)

Inkscape relies on underlying rendering libraries (Pango and Fontconfig on Linux, DirectWrite on Windows, and Core Text on macOS) to handle character rendering:

  • Linux (Fontconfig): You can define machine-wide or user-specific glyph fallback rules by editing ~/.config/fontconfig/fonts.conf. Using <alias> and <prefer> tags allows you to automatically map universal fallbacks (such as Noto Color Emoji or specialized CJK fonts) whenever any application, including Inkscape, encounters an unmapped character code.
  • Windows & macOS: Both systems feature internal font-linking tables. If an entire font stack lacks a glyph and no generic family resolves it, the operating system attempts a last-resort substitute from system fonts like Segoe UI Symbol (Windows) or Apple Symbols (macOS).

Preserving Glyphs for Final Distribution

Font fallback lists rely on the fonts installed on the computer viewing or editing the SVG. If an SVG is viewed on a system missing your specified fallbacks, typography may shift or default to unexpected system fonts.

To permanently preserve glyph rendering for production or print, select your finalized text elements and convert them to vector paths by choosing Path > Object to Path (Ctrl + Shift + C). Note that this renders the text non-editable, so maintain an unlinked, editable copy of your project with the active font stacks as a master file.
