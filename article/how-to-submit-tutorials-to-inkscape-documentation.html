How to Submit Tutorials to Inkscape Documentation

This guide provides a comprehensive walkthrough for artists seeking to contribute official vector tutorial files to the Inkscape documentation repository. It outlines everything from formatting the vector artwork to comply with Inkscape's technical and licensing standards, to using GitLab for repository management, creating a merge request, and collaborating with the documentation team.

1. Review Licensing and Technical Requirements

Before creating or packaging your tutorial file, ensure your work adheres to Inkscape's community standards:

  • Licensing: Official documentation assets are typically distributed under free and open-source licenses, such as the Creative Commons Attribution-ShareAlike (CC-BY-SA) or the GNU General Public License (GPL). You must be willing to release your artwork under these terms.
  • Standard Fonts: Use only open-source, system-neutral fonts (such as DejaVu Sans, Liberation Sans, or Cantarell) to ensure the text renders consistently across Linux, Windows, and macOS without requiring proprietary installations.
  • Clean Code: Use pure Inkscape SVG without unsupported third-party metadata or proprietary extension tags.

2. Prepare the Vector Files

The tutorial files distributed inside Inkscape (accessible via Help > Tutorials) must follow strict structural rules:

  • Clean the Document: Open File > Clean Up Document in Inkscape to purge unused definitions, gradients, patterns, and markers.
  • Optimize Document Properties: Set your canvas dimensions appropriately, ensure the display units are standard (usually pixels or millimeters), and remove unnecessary guides or grids unless they are essential for the tutorial.
  • Layer Organization: Clearly name layers (e.g., "Instructions", "Artwork", "Templates") and lock layers containing static tutorial instructions so users can interact with exercise elements without accidentally moving background panels.
  • File Size: Keep file sizes minimal. Avoid embedded high-resolution raster images unless explicitly required.

3. Create an Account and Fork the Repository

The Inkscape documentation and tutorial source files are hosted on the Inkscape GitLab instance.

  1. Create an account on GitLab.
  2. Navigate to the official Inkscape documentation repository (typically inkscape/inkscape-docs or the main inkscape/inkscape repository for built-in tutorials).
  3. Click the Fork button in the top right to duplicate the repository to your personal GitLab namespace.

4. Clone and Create a Working Branch

Work on a dedicated branch rather than the master or main branch:

  1. Clone your fork locally using Git: 
    git clone https://gitlab.com/<your-username>/inkscape-docs.git
cd inkscape-docs
  2. Create a new descriptive branch: 
    git checkout -b add-vector-tutorial-name

5. Add Your Files to the Proper Directory

Place your .svg tutorial file and any accompanying translation strings or documentation files into the designated tutorial directory:

  • For built-in tutorials, locate the relevant subfolder (usually share/tutorials/ within the source tree).
  • If your tutorial requires internationalization, ensure the SVG text strings are cleanly isolated so that the documentation translation team can process them with standard gettext tools.

6. Commit and Push Your Changes

Commit your files using clear, descriptive commit messages adhering to project conventions:

git add share/tutorials/your-tutorial.svg
git commit -m "Add beginner vector shading tutorial"
git push origin add-vector-tutorial-name

7. Open a Merge Request

  1. Return to your forked repository on GitLab in your browser.
  2. Click Create Merge Request for the recently pushed branch.
  3. Choose the target branch in the upstream Inkscape repository (usually master).
  4. In the merge request description:
    • Explain the goal and target audience of the tutorial.
    • State that you agree to release the asset under the project's documentation license.
    • Note any dependencies or specific Inkscape version requirements.
  5. Submit the Merge Request.

8. Address Feedback and Finalize

Once submitted, members of the Inkscape Documentation and Vectors teams will review your submission for usability, visual consistency, and technical compliance. Monitor the merge request thread to address questions, adjust SVG settings, or push amendments directly to your branch until the request is approved and merged into the official release.
