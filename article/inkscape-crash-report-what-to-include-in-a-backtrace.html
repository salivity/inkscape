Inkscape Crash Report: What to Include in a Backtrace

When reporting an Inkscape crash or freeze to developers, submitting a comprehensive debug backtrace is critical to identifying and fixing the underlying software bug. A useful report requires more than just the raw stack trace; it must supply complete context, including the specific Inkscape build, operating system environment, full debugging symbols, and precise steps to reproduce the issue. Providing this complete information enables developers to locate the exact line of code responsible for the failure without unnecessary back-and-forth communication.

1. The Full Stack Backtrace

The backtrace is the core technical component of the report. It details the active function calls at the moment the crash occurred.

  • Complete Call Stack: Provide the entire backtrace, not just the top few lines. When using GDB (GNU Debugger), generate this using the bt full command rather than just bt. This captures local variable states within each stack frame.
  • Debug Symbols (Debugging Information): A backtrace consisting of memory addresses or lines filled with ?? () is rarely useful. Ensure debug symbols are installed. On Linux, this typically involves installing packages like inkscape-dbgsym or inkscape-dbg. On Windows or macOS, ensure you are testing with a development build that includes debugging information.
  • All Threads: Crashes often occur across multiple threads. A multi-threaded backtrace, captured in GDB via thread apply all bt full, shows the state of every running thread at the time of failure.

2. Inkscape Version and Build Details

Inkscape undergoes frequent updates and is distributed across multiple packaging formats. Clearly identify the specific binary in use.

  • Exact Version String: Run inkscape --version in your terminal and include the complete output, which contains the release version and the exact Git commit hash (e.g., Inkscape 1.3.2 (091e20ef0f, 2023-11-25)).
  • Installation Method: Specify how Inkscape was installed. State whether you are using a native distribution package (e.g., APT, DNF, Pacman), Flatpak, Snap, AppImage, macOS DMG, or Windows installer (MSI/exe).

3. Operating System and Environment

System-level discrepancies often dictate how libraries interact with Inkscape.

  • Operating System: Name and version (e.g., Ubuntu 22.04 LTS, Windows 11 23H2, macOS Sonoma 14.4).
  • Architecture: Specify your CPU architecture (e.g., x86_64, ARM64/Apple Silicon).
  • Display Server (Linux): Indicate whether the crash occurs under Wayland or X11.
  • Desktop Environment / Window Manager: Note if you are using GNOME, KDE Plasma, XFCE, or a tiling window manager.
  • Relevant Hardware: Note graphics card models and drivers (e.g., NVIDIA proprietary drivers vs. Mesa), especially if the issue involves hardware acceleration, canvas rendering, or display scaling.

4. Console and Terminal Output

Inkscape often writes diagnostic information, warnings, and non-fatal assertions to standard output and standard error before a crash occurs.

  • Launch Inkscape directly from a terminal window.
  • Copy and paste the terminal log from the moment of launch through the crash. Look for GTK warnings, GLib critical errors, or Python extension exceptions.

5. Steps to Reproduce

A backtrace explains where the crash happened, but reproduction steps explain how to trigger it.

  • Step-by-Step Instructions: Provide an ordered list of exact actions (e.g., "1. Select the Pen tool. 2. Click once on the canvas. 3. Press Shift+Ctrl+F.").
  • Input Method Details: Mention if specific hardware was used during the crash, such as a graphics tablet, stylus, or multi-touch trackpad.
  • Minimal Reproduction Case: Simplify the steps as much as possible, isolating the single action that triggers the fault.

6. Minimal Test File (SVG)

If the crash is related to a specific document or file operation, attach the affected file.

  • Isolate the Fault: Do not submit massive production files. Strip the document down to the minimal number of nodes, layers, or filters necessary to trigger the bug.
  • Embedded Assets: If the crash involves raster images or external fonts, ensure they are embedded or clearly identified in the report.

7. Inkscape Configuration State

Occasionally, corrupted preferences or third-party extensions cause crashes.

  • Note whether the crash still occurs when using a clean preferences file (temporarily renaming or moving preferences.xml).
  • List any active third-party extensions, custom themes, or modified keyboard shortcut layouts.
