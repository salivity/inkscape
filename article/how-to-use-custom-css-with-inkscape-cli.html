How to Use Custom CSS with Inkscape CLI

This article outlines how to apply external or custom CSS files to override rendering styles when exporting graphics using the Inkscape Command Line Interface (CLI). While Inkscape does not provide a standalone, direct --css command-line flag, you can achieve full styling overrides by dynamically injecting your stylesheet into the SVG document structure prior to or during CLI processing using shell pipelines and standard XML techniques.

Understanding Inkscape CLI Styling Limitations

Inkscape adheres to W3C SVG standards for rendering, using internal style attributes, inline <style> blocks, and standard XML stylesheet references (<?xml-stylesheet ?>). Because the Inkscape CLI lacks a dedicated argument like --custom-css=style.css, overriding styles during a batch or automated export requires inserting the CSS reference directly into the SVG file's XML hierarchy before passing it to Inkscape's rendering engine.

Method 1: Injecting CSS via Standard Input (--pipe)

The cleanest method to override styles without permanently altering the source SVG file is using Inkscape's standard input processing via the --pipe argument. You can use command-line text stream utilities like sed or awk to dynamically inject an inline <style> tag containing your custom CSS.

CSS_CONTENT=$(cat custom.css)
sed "s|</svg>|<style><![CDATA[${CSS_CONTENT}]]></style></svg>|" input.svg | inkscape --pipe --export-filename=output.png

To export to PDF while overriding styles:

sed "s|</svg>|<style><![CDATA[$(cat custom.css)]]></style></svg>|" input.svg | inkscape --pipe --export-type=pdf --export-filename=output.pdf

Using standard input ensures the source SVG remains untouched while applying your custom rules, including !important declarations to override existing inline attributes.

Method 2: Linking an External Stylesheet with xmlstarlet

If you prefer referencing an external .css file directly rather than embedding its contents, add an xml-stylesheet processing instruction to the SVG header using xmlstarlet before calling Inkscape.

  1. Insert the processing instruction into a temporary copy:
xmlstarlet ed -i "/svg" -t pi -n "xml-stylesheet" -v 'type="text/css" href="custom.css"' input.svg > temp.svg
  1. Render the updated file with Inkscape:
inkscape temp.svg --export-type=png --export-filename=output.png
  1. Remove the temporary file:
rm temp.svg

For this method to work, custom.css must reside in the same working directory as the target SVG, or the href attribute must contain a valid relative or absolute file path.

Overriding Specific Inline Styles

SVGs generated by graphic editors frequently use presentation attributes (such as fill="...") or inline styles (style="fill:...;"). CSS rules applied through an external or injected stylesheet take precedence over standard XML presentation attributes. However, to reliably override inline style="" declarations defined on individual elements, ensure your custom CSS rules include the !important directive:

/* custom.css */
path, rect, circle {
    fill: #ff0000 !important;
    stroke: #000000 !important;
    stroke-width: 2px !important;
}
