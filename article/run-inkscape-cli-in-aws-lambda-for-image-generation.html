Run Inkscape CLI in AWS Lambda for Image Generation

Running Inkscape via the command-line interface (CLI) inside AWS Lambda enables scalable, on-demand vector graphics manipulation, format conversion, and dynamic asset generation without managing persistent servers. Because Inkscape depends on extensive graphical and font libraries that exceed standard Lambda zip layer constraints, deploying it as a container image via Amazon Elastic Container Registry (ECR) provides the most reliable architecture. This guide walks through configuring a containerized Lambda environment, invoking the Inkscape CLI through a runtime handler, and properly configuring execution settings for optimal performance.

1. Create the Dockerfile

Inkscape requires several system-level dependencies, including GTK, Cairo, and font packages. Using a Debian or Ubuntu base image with the AWS Lambda Runtime Interface Client (RIC) is the most straightforward way to install standard package versions of Inkscape.

Create a Dockerfile:

FROM python:3.11-slim

# Install system dependencies, Inkscape, and required fonts
RUN apt-get update && apt-get install -y \
    inkscape \
    fonts-dejavu-core \
    fonts-freefont-ttf \
    g++ \
    make \
    cmake \
    unzip \
    libcurl4-openssl-dev \
    && rm -rf /var/lib/apt/lists/*

# Install AWS Lambda Runtime Interface Client
RUN pip install --no-cache-dir awslambdaric boto3

# Set the working directory
WORKDIR /var/task

# Copy application files
COPY app.py .

# Configure Lambda entrypoint
ENTRYPOINT ["/usr/local/bin/python", "-m", "awslambdaric"]
CMD ["app.handler"]

2. Write the Lambda Handler

The Lambda handler receives the input (such as raw SVG data or an Amazon S3 source key), writes the input file to the writable /tmp directory, executes the Inkscape CLI via Python's subprocess module, and handles the output file.

Create app.py:

import subprocess
import os
import base64
import json

def handler(event, context):
    input_path = "/tmp/input.svg"
    output_path = "/tmp/output.png"

    # Clean up previous runs if the container is warm
    for path in [input_path, output_path]:
        if os.path.exists(path):
            os.remove(path)

    # Extract SVG data from the event payload
    svg_data = event.get("svg_data")
    if not svg_data:
        return {
            "statusCode": 400,
            "body": json.dumps({"error": "No svg_data provided"})
        }

    # Write SVG to ephemeral storage
    with open(input_path, "w", encoding="utf-8") as f:
        f.write(svg_data)

    # Execute Inkscape CLI command
    # Converts SVG to PNG at 300 DPI
    command = [
        "inkscape",
        input_path,
        "-o", output_path,
        "--export-dpi=300"
    ]

    try:
        result = subprocess.run(
            command,
            stdout=subprocess.PIPE,
            stderr=subprocess.PIPE,
            check=True
        )
    except subprocess.CalledProcessError as e:
        return {
            "statusCode": 500,
            "body": json.dumps({
                "error": "Inkscape execution failed",
                "details": e.stderr.decode("utf-8")
            })
        }

    # Read the output image and encode to base64
    with open(output_path, "rb") as f:
        output_bytes = f.read()

    return {
        "statusCode": 200,
        "headers": {"Content-Type": "image/png"},
        "isBase64Encoded": True,
        "body": base64.b64encode(output_bytes).decode("utf-8")
    }

3. Build and Push the Container Image

To deploy the container to AWS Lambda, build the Docker image locally and push it to Amazon Elastic Container Registry (ECR).

Authenticate your local Docker client to ECR:

aws ecr get-login-password --region <region> | docker login --username AWS --password-stdin <account_id>.dkr.ecr.<region>.amazonaws.com

Create a repository (if not already created):

aws ecr create-repository --repository-name lambda-inkscape --region <region>

Build, tag, and push the image:

docker build -t lambda-inkscape .
docker tag lambda-inkscape:latest <account_id>.dkr.ecr.<region>.amazonaws.com/lambda-inkscape:latest
docker push <account_id>.dkr.ecr.<region>.amazonaws.com/lambda-inkscape:latest

4. Deploy and Configure the Lambda Function

Create the Lambda function using the container image via the AWS Console or the AWS CLI:

aws lambda create-function \
    --function-name inkscape-renderer \
    --package-type Image \
    --code ImageUri=<account_id>.dkr.ecr.<region>.amazonaws.com/lambda-inkscape:latest \
    --role <lambda-execution-role-arn> \
    --timeout 30 \
    --memory-size 2048

Critical Configuration Settings

  • Memory Allocation: Allocate at least 1536 MB to 2048 MB of RAM. Inkscape requires sufficient memory to initialize its graphical libraries and parse vector paths. Adding memory also allocates proportional vCPU power, significantly decreasing rendering times.
  • Timeout: Set the timeout to a minimum of 30 seconds. Complex vector files with high-density paths or high-DPI rasterization steps will take longer to export than simple geometric shapes.
  • Ephemeral Storage (/tmp): Default storage is 512 MB. If you are processing high-resolution assets or multi-page documents, expand /tmp capacity under the Lambda configuration tab up to the required size (up to 10 GB).
