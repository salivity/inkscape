Enable Inkscape Cairo Debug Messages on Stderr

This guide explains how to enable developer debug messages on standard error (stderr) to capture and diagnose Cairo rendering failures in Inkscape. By launching Inkscape from a terminal, configuring GLib and GTK environment variables, and capturing low-level graphics calls, developers and troubleshooters can pinpoint the exact operations causing Cairo rendering pipeline crashes or graphic corruption.

1. Launch Inkscape from the Command Line

By default, GUI applications suppress standard output and standard error streams. To view diagnostic output, launch Inkscape directly from your system console:

  • Linux / macOS: Open a terminal and run inkscape.
  • Windows: Use the Command Prompt or PowerShell and launch inkscape.com (not inkscape.exe), as the .com wrapper automatically pipes standard error and standard output to the console window: 
    "C:\Program Files\Inkscape\bin\inkscape.com"

To save the standard error stream to a log file for analysis, redirect stderr:

inkscape 2> cairo_debug.log

2. Set Debug Environment Variables

Inkscape utilizes GLib's structured logging system to output diagnostic statements from internal components, including Cairo rendering routines. You can enable full diagnostic messaging by setting G_MESSAGES_DEBUG before running Inkscape.

Linux / macOS

export G_MESSAGES_DEBUG=all
inkscape

To isolate Inkscape-specific messages while filtering out unrelated system libraries, target the application namespace:

export G_MESSAGES_DEBUG=org.inkscape.Inkscape
inkscape

Windows (Command Prompt)

set G_MESSAGES_DEBUG=all
inkscape.com

Windows (PowerShell)

$env:G_MESSAGES_DEBUG="all"
inkscape.com

3. Treat Cairo Warnings as Fatal

Cairo issues critical warnings on stderr when drawing surfaces enter an error state (such as out-of-memory errors, invalid matrix operations, or null pointers). Because Cairo often attempts to recover gracefully, the rendering failure might manifest as a blank canvas rather than an application crash.

Force Inkscape to halt execution at the exact moment a Cairo error occurs by passing the fatal warning flag:

inkscape --g-fatal-warnings

Alternatively, set the GLib debug variable:

export G_DEBUG=fatal-criticals,fatal-warnings
inkscape

When coupled with a debugger like GDB, this forces the application to break directly on the offending Cairo function call:

gdb --args inkscape --g-fatal-warnings
(gdb) run
(gdb) bt

The backtrace (bt) will show the exact stack frame within Cairo (such as _cairo_set_source or cairo_stroke) where the failure initiated.

4. Capture Low-Level Calls with cairo-trace

If standard error logs do not provide enough context regarding what caused Cairo to fail, use cairo-trace (available via the cairo-utils package on most Linux distributions) to generate an execution log of every single Cairo call:

cairo-trace inkscape

This generates a .trace file containing human-readable graphics instructions up to the point of failure, enabling you to inspect the precise SVG path, clip mask, or color space that triggered the rendering fault.
