Transfer SVG Between Inkscape and Affinity Designer

Transferring vector artwork between Inkscape and Affinity Designer requires relying on standard SVG specifications to avoid compatibility errors. While both applications support SVG natively, each introduces proprietary namespaces, layer structures, and unit interpretations that can lead to shifted elements, broken gradients, or altered text. This guide outlines the exact export presets, scaling adjustments, and formatting practices needed to create a frictionless two-way vector pipeline.

Inkscape to Affinity Designer: Export Best Practices

  1. Save as Plain SVG: Inkscape defaults to saving files as "Inkscape SVG," which includes proprietary Sodipodi and Inkscape XML metadata. To prepare a file for Affinity Designer, navigate to File > Save As... and select Plain SVG (*.svg) from the file type dropdown. This strips Inkscape-specific attributes, preserving standard W3C-compliant elements.
  2. Convert Objects and Text to Paths: Dynamic features like Inkscape Live Path Effects (LPE) or specialized flow-text do not translate natively into Affinity Designer. Select dynamic shapes and choose Path > Object to Path before saving. For text elements where font consistency across machines cannot be guaranteed, convert text to vector paths using the same command.
  3. Resolve Clones and Clips: Linked clones in Inkscape (<use> tags) can sometimes render incorrectly in Affinity. Unlink clones (Edit > Clone > Unlink Clone) to convert them into independent path duplicates.

Affinity Designer to Inkscape: Export Best Practices

  1. Choose the Right SVG Preset: Navigate to File > Export and choose SVG. Open the Preset menu and select SVG (for export). Avoid "SVG (flattened)" or presets intended purely for web optimization that might strip essential vector data.
  2. Configure Advanced Export Settings: Under the More options in the SVG export dialog:
    • Uncheck Rasterise: Set this to "Nothing" to prevent Affinity from turning unsupported vector properties into embedded PNG bitmaps.
    • Enable Set viewBox: This ensures that Inkscape accurately maps the boundaries and coordinate system of the artwork.
    • Set DPI to 96: Affinity Designer often defaults to 72 DPI or 300 DPI. Because Inkscape adheres strictly to the CSS standard of 96 DPI, exporting at 96 DPI prevents unwanted resizing when opened in Inkscape.
  3. Convert Curves on Export: Check the box labeled Convert text to curves if the target environment in Inkscape does not have access to identical system fonts.

Managing Common Cross-Platform Incompatibilities

  • Layer Handling: Inkscape creates layers using standard SVG group tags with custom metadata (<g inkscape:groupmode="layer">). Affinity Designer reads these as regular groups. When moving back from Affinity to Inkscape, top-level groups will appear as normal groups rather than Inkscape layers; you can convert them back by right-clicking the group in Inkscape's Layers panel and selecting Convert to Layer.
  • Gradient Coordinates: Both programs handle linear and radial gradients cleanly, but complex multi-stop gradient meshes or non-standard vector fills should be simplified, as gradient mesh translation between the two tools is not supported by standard SVG 1.1.
  • Clipping and Masking: Nested masks can introduce translation errors. Use standard vector clipping paths instead of raster-based opacity masks to ensure outlines remain fully editable on both sides of the bridge.
