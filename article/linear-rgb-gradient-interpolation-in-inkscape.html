Linear RGB Gradient Interpolation in Inkscape

This article explores the mathematical process Inkscape uses to calculate gradient color interpolation in linear RGB space. When the color-interpolation="linearRGB" SVG attribute is active, Inkscape departs from standard perceptual gamma-corrected blending to preserve physical light energy ratios. To achieve this, Inkscape executes a three-stage mathematical pipeline: transforming sRGB values to non-gamma-encoded linear intensities, calculating standard weighted linear interpolations (LERP) across the gradient line, and transforming the resulting linear values back into the non-linear sRGB color space for display output.

1. Linearization (De-Gamma Transformation)

Digital colors in Inkscape are natively defined in the non-linear sRGB color space, which applies a gamma curve to match human visual perception. Before interpolating in linear space, the color stop values must be linearized.

Given a normalized sRGB color component \(C_{sRGB} \in [0, 1]\), Inkscape adheres to the standard IEC 61966-2-1 piecewise function to derive the linear intensity \(C_{linear}\):

\[C_{linear} = \begin{cases} \frac{C_{sRGB}}{12.92}, & \text{if } C_{sRGB} \le 0.04045 \\ \left( \frac{C_{sRGB} + 0.055}{1.055} \right)^{2.4}, & \text{if } C_{sRGB} > 0.04045 \end{cases}\]

This operation is applied independently to the Red, Green, and Blue color channels of each adjacent gradient stop.

2. Linear Interpolation (LERP)

Once the color stops are mapped into a linear coordinate space, intermediate colors along the gradient vector are calculated using standard linear interpolation based on a normalized distance parameter \(t \in [0, 1]\).

For two adjacent stops, \(Stop_1\) at position \(t = 0\) and \(Stop_2\) at position \(t = 1\), the interpolated linear component \(C_{interp}(t)\) is calculated as:

\[C_{interp}(t) = (1 - t) \cdot C_{linear, 1} + t \cdot C_{linear, 2}\]

Premultiplied Alpha Handling

If opacity varies between the color stops, Inkscape computes the gradient in premultiplied space to avoid rendering artifacts at transparent boundaries. The linear color components are scaled by the alpha channel prior to interpolation:

\[C'_{linear} = C_{linear} \cdot \alpha\]

\[\alpha_{interp}(t) = (1 - t) \cdot \alpha_1 + t \cdot \alpha_2\]

\[C'_{interp}(t) = (1 - t) \cdot C'_{linear, 1} + t \cdot C'_{linear, 2}\]

If the output format requires straight (unpremultiplied) colors, the color component is recovered by dividing by the interpolated alpha:

\[C_{final\_linear}(t) = \frac{C'_{interp}(t)}{\alpha_{interp}(t)} \quad (\text{where } \alpha_{interp}(t) > 0)\]

3. Display Re-Encoding (Gamma Encoding)

Modern display hardware expects gamma-compressed inputs. Therefore, the interpolated linear values must be converted back to the sRGB color space using the inverse transfer function:

\[C_{sRGB} = \begin{cases} 12.92 \cdot C_{final\_linear}, & \text{if } C_{final\_linear} \le 0.0031308 \\ 1.055 \cdot (C_{final\_linear})^{\frac{1}{2.4}} - 0.055, & \text{if } C_{final\_linear} > 0.0031308 \end{cases}\]

The resulting \(C_{sRGB}\) values are then quantized into standard 8-bit integers (\([0, 255]\)) for rendering on the screen. By performing the interpolation in the linear domain between the de-gamma and re-gamma stages, Inkscape eliminates the "dark bands" commonly seen in standard sRGB transitions between complementary hues.
