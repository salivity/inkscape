Automated Testing for Inkscape Extensions Using inkex

This guide demonstrates how to build and execute automated regression tests for custom Inkscape extensions using the built-in inkex.tester module. By leveraging the framework's test harness, you can isolate extension behavior, supply test vector files, and automatically assert that generated SVG output matches established reference files to prevent breaking changes across updates.

Setting Up the Test Directory Structure

The inkex testing framework relies on a predictable file organization to discover test inputs and verify them against expected reference outputs. Place your test scripts and sample data in a dedicated tests directory within your extension's root folder:

my_extension/
├── my_extension.py
├── my_extension.inx
└── tests/
    ├── test_my_extension.py
    └── data/
        ├── input/
        │   └── basic_shape.svg
        └── refs/
            └── basic_shape.svg

The data/input directory holds the original SVG files prior to extension processing. The data/refs directory holds the exact, expected SVG or text output that the extension should generate after modification.

Creating the Test Case

Inkscape provides the ComparisonMixin and TestCase classes inside inkex.tester. Combining these classes allows you to test your extension against multiple combinations of command-line arguments and input files with minimal boilerplate.

Create a test file (e.g., tests/test_my_extension.py) with the following implementation:

from inkex.tester import ComparisonMixin, TestCase
from my_extension import MyCustomExtension

class TestMyCustomExtension(ComparisonMixin, TestCase):
    # Specify the extension class to instantiate
    effect_class = MyCustomExtension

    # Define test combinations: (args_tuple, input_filename)
    comparisons = [
        # Tests default execution on basic_shape.svg
        (),
        # Tests specific CLI arguments passed to the extension
        ("--custom-param=42", "--mode=outline"),
    ]

When no file is explicitly tied to a comparison tuple, inkex will attempt to use default test SVG files or files defined in the test class. To specify an input file directly alongside arguments:

class TestMyCustomExtensionWithFiles(ComparisonMixin, TestCase):
    effect_class = MyCustomExtension

    comparisons = [
        # Format: (args_list, input_filename)
        (["--custom-param=100"], "basic_shape.svg"),
    ]

How the Comparison Works

During execution, ComparisonMixin processes the test in several steps:

  1. Loads the Input File: It reads the designated file from tests/data/input/.
  2. Executes the Extension: It initializes your effect_class, parses the provided argument list, and executes the extension's logic in-memory.
  3. Compares to Reference: It extracts the output SVG document and compares its XML structure against the corresponding file in tests/data/refs/.

The framework normalizes XML attributes, element order, and floating-point precision differences, ensuring tests do not fail on minor syntactic variations between environments.

Generating Initial Reference Files

When writing a new test, you must generate the initial reference file to establish baseline expectations.

  1. Ensure your input file exists in tests/data/input/basic_shape.svg.
  2. Set the environment variable EXPORT_COMPARE to automatically write the generated output directly to the references folder during execution:
EXPORT_COMPARE=true pytest tests/test_my_extension.py
  1. Open the newly generated file inside tests/data/refs/ in a text editor or Inkscape to manually verify that the output is correct. Once verified, commit this file to your version control system.

Running the Regression Tests

The inkex test suite is compatible with pytest. Run your test suite from your extension's root directory:

pytest

To run only a specific test class or method with verbose output:

pytest tests/test_my_extension.py -v

If an update alters the generated SVG structure, pytest will report a failure and display a unified XML diff indicating precisely which nodes, attributes, or text contents changed, allowing you to catch unintended visual and programmatic regressions instantly.
