How Inkscape Edits Change SVG linearGradient

This article explains how interactive edits made with Inkscape’s Gradient Tool directly alter the underlying SVG <linearGradient> element. By understanding the relationship between the canvas handles, the color palette, and the raw XML, you can see how adjustments to gradient direction, stop positions, colors, and transformations dynamically update specific attributes such as x1, y1, x2, y2, <stop> tags, and Inkscape's gradient inheritance structure.

Vector Position and Orientation (x1, y1, x2, y2)

When you select an object with the Gradient Tool (G) in Inkscape, a control line appears with two primary endpoints: a square (start) and a circle (end).

  • Moving the Start Handle: Adjusting the square handle changes the x1 and y1 attributes of the <linearGradient> tag.
  • Moving the End Handle: Adjusting the circle handle changes the x2 and y2 attributes.
  • Coordinate Systems: By default, Inkscape usually sets gradientUnits="userSpaceOnUse". This means the coordinate values directly represent absolute positions on the document canvas rather than percentage-based fractions of the object’s bounding box (objectBoundingBox).

Gradient Stops and Color Values (<stop>)

Every color transition point along the gradient vector is represented as a child <stop> element within the <linearGradient> definition.

  • Adding Stops: Double-clicking the gradient line on the canvas adds a diamond-shaped handle. In the SVG source, this inserts a new <stop> element.
  • Adjusting Position: Dragging a diamond handle along the vector updates the offset attribute of that stop. The value ranges from 0 (or 0%) at the start to 1 (or 100%) at the end.
  • Changing Colors and Opacity: Selecting a handle and picking a color or changing the alpha slider in the Fill and Stroke panel updates stop-color and stop-opacity (or the equivalent properties inside a style attribute).

Inkscape's Two-Part Gradient Architecture (xlink:href)

Inkscape typically handles gradients using an inheritance pattern to allow multiple objects to share the same color ramp:

  1. The Base Definition: Inkscape creates an abstract <linearGradient> in the <defs> section containing only the <stop> tags and an id (e.g., id="linearGradient1234").
  2. The Applied Gradient: A second <linearGradient> tag references the first using xlink:href="#linearGradient1234" (or href="#linearGradient1234" in SVG 2). This second element contains the position-specific attributes (x1, y1, x2, y2, and gradientTransform).

When you modify the colors of a shared gradient on the canvas, Inkscape updates the base definition, affecting all instances. When you reposition the gradient handles for a single object, only the applied gradient's coordinates are modified.

Transformations (gradientTransform)

If you move, scale, or rotate an object with the "Transform gradients in place" toggle enabled in the tool controls bar, Inkscape does not rewrite the raw x and y coordinates. Instead, it adds or updates a gradientTransform attribute on the gradient element. This attribute contains matrix operations (such as matrix(...) or rotate(...)) ensuring the gradient maintains its relative orientation and scale to the shape.

Repeat and Reflection (spreadMethod)

Inkscape allows you to change how a gradient behaves outside its start and end points via the Gradient Tool controls bar. Changing this setting directly updates the spreadMethod attribute:

  • None (Default): Maps to spreadMethod="pad", extending the terminal colors outward indefinitely.
  • Reflect: Maps to spreadMethod="reflect", mirroring the color sequence repeatedly.
  • Repeat: Maps to spreadMethod="repeat", restarting the sequence from the beginning in a continuous loop.
