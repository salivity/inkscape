How Inkscape Calculates Path Offset Distances

This article explores the mathematical framework Inkscape uses to compute path offset distances, including Inset, Outset, and Dynamic Offset operations. Because exact offsets of cubic Bézier curves cannot be represented as standard Bézier curves, Inkscape relies on specialized geometric approximation algorithms implemented in its internal libraries, primarily Livarot and lib2geom. The following sections break down the underlying mathematical challenge, the step-by-step algorithms used to calculate offset paths, and how intersections and curve fitting are resolved.

The Mathematical Problem of Bézier Offsets

Vector software like Inkscape defines shapes using piecewise parametric cubic Bézier curves. Mathematically, an offset curve \(C_d(t)\) at a distance \(d\) from a base curve \(C(t)\) is defined as:

\[C_d(t) = C(t) + d \cdot N(t)\]

where \(N(t)\) is the unit normal vector to the curve at parameter \(t\):

\[N(t) = \frac{(-y'(t), x'(t))}{\sqrt{x'(t)^2 + y'(t)^2}}\]

Because of the square root in the denominator representing the Euclidean norm, the resulting offset curve is generally non-polynomial and non-rational. For a cubic Bézier curve, the exact algebraic offset is an algebraic curve of degree 10, meaning it cannot be natively represented using cubic Bézier segments. Consequently, Inkscape must approximate the offset mathematically.

Inkscape's Offset Pipeline

Inkscape calculates path offsets through a multi-stage geometric algorithm handled primarily by the Livarot geometry library (used for destructive operations like Path > Inset / Outset) and modern implementations in lib2geom (used for non-destructive Live Path Effects):

1. Adaptive Polyline Discretization

The algorithm first samples the original Bézier curves and converts them into an adaptive polyline approximation. Curves with higher curvature are subdivided more finely using a tolerance threshold to ensure the geometric deviation between the true curve and the linear approximation remains negligible.

2. Parallel Normal Displacement

Once the path is converted into a series of straight line segments, computing the offset becomes mathematically straightforward:

  • Each line segment is translated along its perpendicular normal vector by the signed distance \(d\) (positive for outset, negative for inset).
  • Vertices between adjacent segments are connected using mitered projections, rounded arc fillets, or beveled segments depending on the join style specified.

3. Topology Cleanup and Self-Intersection Removal

Offsetting curves inward (inset) often introduces loops, cusps, and self-intersections where the offset distance exceeds the local radius of curvature (\(d > 1/\kappa\)).

  • The algorithm uses a sweep-line algorithm (Bentley-Ottmann style) to detect all intersection points within the offset polyline.
  • A planar graph of the offset segments is constructed.
  • Using winding number rules (even-odd or non-zero), invalid internal loops and overlapping regions are culled, leaving only the correct outer boundary.

4. Spline Fitting (Bézier Re-parameterization)

The cleaned polyline must be converted back into smooth cubic Bézier curves to match Inkscape's SVG data format.

  • Inkscape employs a least-squares curve-fitting algorithm (derived from Philip J. Schneider’s method for fitting curves to digitizer data).
  • The algorithm identifies corners (points with discontinuous tangents) and fits cubic Bézier segments between them.
  • If the maximum error between a fitted segment and the offset polyline exceeds an internal tolerance threshold, the segment is split at the point of maximum deviation, and the process repeats recursively until the target precision is reached.

Dynamic Offsets vs. Standard Offsets

Standard Inset and Outset operations perform this pipeline destructively, baking the resulting fitted Bézier control points directly into the SVG path. Dynamic Offsets use an algorithmic Live Path Effect (LPE) wrapper that recalculates the offset polyline and curve fitting continuously in real time as the control handle adjusts the distance parameter \(d\).
