How to Create an Inkscape INX Extension Manifest

An Inkscape Extension (.inx) file is an XML manifest that defines how a custom script integrates into Inkscape. It dictates the metadata, the user interface dialog, menu placement, and execution commands needed to run the accompanying script (typically Python). Creating a functional .inx file requires establishing a root <inkscape-extension> element containing child elements for identification, input parameters, script bindings, and menu hierarchy.

Basic Structure of an .inx File

An .inx file must be saved in Inkscape's extensions directory alongside your backend script. The overall structure consists of several primary sections wrapped inside an XML declaration and a root <inkscape-extension> tag.

<?xml version="1.0" encoding="UTF-8"?>
<inkscape-extension xmlns="http://www.inkscape.org/namespace/inkscape/extension">
    <name>My Custom Tool</name>
    <id>org.example.inkscape.my_custom_tool</id>

    <!-- UI Parameters -->
    <param name="tab" type="notebook">
        <page name="options" gui-text="Options">
            <param name="user_text" type="string" gui-text="Enter text:">Default Text</param>
            <param name="amount" type="int" min="1" max="100" gui-text="Copies:">1</param>
            <param name="enable_feature" type="bool" gui-text="Apply feature">true</param>
        </page>
    </param>

    <!-- Effect Configuration and Menu Placement -->
    <effect>
        <object-type>all</object-type>
        <effects-menu>
            <submenu gui-text="Modify"/>
        </effects-menu>
    </effect>

    <!-- Script Execution -->
    <script>
        <command location="inx" interpreter="python">my_script.py</command>
    </script>
</inkscape-extension>

Core XML Elements

1. Metadata and Identification

Every extension requires a human-readable display name and a unique identifier:

  • <name>: Defines the label visible to users inside Inkscape’s menu.
  • <id>: A unique string identifier, typically structured using reverse domain notation (for example, org.inkscape.effect.mytool), to prevent conflicts with other extensions.

2. User Interface Parameters (<param>)

The <param> tag defines input fields that appear in the extension dialog window. Each parameter maps directly to command-line flags passed to the execution script.

  • name: The command-line argument name (e.g., name="amount" maps to --amount in the script).
  • type: The data type, such as string, int, float, bool, color, optiongroup, or notebook.
  • gui-text: The text label displayed next to the control in the UI.
  • The text content inside the tag defines the default value.

For complex interfaces, use type="notebook" with <page> tags to create multi-tab layouts.

3. Menu Placement (<effect>)

The <effect> section controls where the extension appears in the Inkscape interface and what document objects it interacts with:

  • <object-type>: Specifies the target elements (typically all).
  • <effects-menu>: Determines the path inside the Extensions menu.
    • <submenu gui-text="Custom Group"/>: Nests the extension inside a specific category (such as Render, Modify Path, or a custom submenu). Omitting this places the extension directly in the root of the Extensions menu.

4. Backend Execution (<script>)

The <script> tag tells Inkscape how to execute the code when the user clicks Apply:

  • <command>: Specifies the execution instructions.
    • interpreter: Set to python to invoke Inkscape's internal Python environment.
    • location: Set to inx to indicate that the script resides in the same directory as the .inx file.
    • Tag value: The filename of the target script (e.g., my_script.py).
