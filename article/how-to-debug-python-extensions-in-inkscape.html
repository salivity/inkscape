How to Debug Python Extensions in Inkscape

Debugging Python extensions inside Inkscape can be challenging because extensions run as independent subprocesses without an interactive terminal attached. This guide outlines the most effective techniques to inspect and debug your custom inkex-based scripts, ranging from command-line execution and logging to real-time interactive debugging using IDEs like Visual Studio Code and PyCharm.

1. Run Extensions from the Command Line

The simplest way to debug is to run your extension outside Inkscape using a standard terminal. Inkscape extensions take an SVG file as an argument and write the modified SVG to standard output.

  1. Save a sample SVG file to your working directory.
  2. Run your script via your terminal: 
    python my_extension.py sample.svg > output.svg
  3. Use Python's built-in debugger by inserting breakpoint() or import pdb; pdb.set_trace() directly into your code. When executed in the terminal, execution will pause and provide an interactive debugging prompt.

2. Remote Debugging with Visual Studio Code (debugpy)

To debug an extension while executing it directly through the Inkscape graphical interface, you can attach a remote debugger using debugpy.

Step 1: Install debugpy

Ensure debugpy is installed in the Python environment that Inkscape uses.

  • On Linux/macOS: Install it via pip install debugpy in your system or virtual environment.
  • On Windows: Use the pip executable located within the Inkscape installation directory (e.g., Inkscape/bin/python.exe -m pip install debugpy).

Step 2: Add the Debug Hook to Your Script

Add the following snippet near the top of your extension's Python file:

import debugpy

# Enable the debugger to listen on port 5678
debugpy.listen(("127.0.0.1", 5678))
# Pause execution until the debugger attaches
debugpy.wait_for_client()

Step 3: Configure VS Code

Create an attach configuration in your .vscode/launch.json file:

{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Python: Attach to Inkscape",
      "type": "debugpy",
      "request": "attach",
      "connect": {
        "host": "127.0.0.1",
        "port": 5678
      },
      "pathMappings": [
        {
          "localRoot": "${workspaceFolder}",
          "remoteRoot": "${workspaceFolder}"
        }
      ]
    }
  ]
}

Step 4: Run and Attach

  1. Trigger the extension inside Inkscape. Inkscape will appear to freeze temporarily; it is waiting for the debugger to connect.
  2. Start the "Python: Attach to Inkscape" configuration in VS Code.
  3. Your breakpoints in VS Code will now trigger as the extension runs.

3. Use inkex.utils.debug() and Error Logging

If you only need quick inspection without a full debugger attached, utilize Inkscape’s built-in messaging features or file logging.

  • Inkscape Dialog Output: Use inkex.utils.debug(variable) or inkex.errormsg("Message"). Anything printed to sys.stderr is captured by Inkscape and displayed in a popup dialog box once the extension finishes running.
  • File Logging: Write debugging information to a persistent file on disk to inspect execution paths without interrupting the user interface:
import logging

logging.basicConfig(
    filename='/path/to/extension_debug.log',
    level=logging.DEBUG,
    format='%(asctime)s - %(levelname)s - %(message)s'
)

logging.debug("Extension initialized.")

4. Inspecting Extension XML Output

Extensions communicate with Inkscape via XML through stdout. If an extension fails silently or produces unexpected visual results, redirect stdout to a file when executing via the command line and inspect the resulting SVG tree using a text editor or XML validator to ensure element IDs and namespaces remain valid.
