Inkscape Path Simplify on Geometric Primitives

This article explains how Inkscape handles the Path Simplify command (Ctrl + L) when executed directly on native geometric primitives such as rectangles, ellipses, stars, and spirals. Applying this command triggers an automatic conversion from a parametric shape into a standard Bezier path, permanently removes native shape-editing handles, and recalculates the object's nodes using Inkscape's simplification algorithm.

Automatic Conversion to Paths

Inkscape geometric primitives (rectangles, circles, ellipses, stars, polygons, and spirals) are stored internally as parametric SVG elements rather than standard vector paths. When you invoke the Path > Simplify command on any of these primitives without first manually selecting Path > Object to Path, Inkscape does not reject the command. Instead, it performs an implicit conversion, converting the primitive into a standard <path> element in the background before running the simplification process.

Loss of Parametric Handles and Attributes

The most immediate consequence of simplifying a geometric primitive is the permanent loss of its dedicated shape controls:

  • Rectangles: You lose the circular corner-rounding handles and the ability to adjust width and height parametrically via the Rectangle tool.
  • Ellipses and Circles: You lose the ability to create segments, arcs, or pie slices using the native arc handles.
  • Stars and Polygons: You lose the ability to dynamically change the number of corners, spoke ratios, or rounding values.
  • Spirals: You lose the handles that control the number of turns and inner/outer radius expansion.

Once simplified, the object can only be edited using the Node tool (N), just like any standard vector path.

Node Reduction and Geometric Distortion

After converting the primitive to a path, Inkscape immediately runs its node-reduction algorithm based on the threshold configured in your Inkscape Preferences (Preferences > Behavior > Steps > Simplification threshold).

The impact on the shape depends heavily on the geometry of the original primitive:

  • Sharp Corners and Rectangles: A basic rectangle initially converts to four nodes. Simplifying it can round off or displace sharp 90-degree corners, turning straight edges into subtle curves depending on the simplification tolerance.
  • Circles and Ellipses: Standard ellipses convert to four smooth nodes. Simplifying them often removes or redistributes these nodes, resulting in an asymmetrical or visibly warped oval.
  • Complex Shapes (Stars and Spirals): Stars and spirals inherently contain many direction changes. Running Simplify will aggressively merge adjacent nodes, round off sharp star tips, and flatten the continuous curvature of spirals. Repeatedly pressing Ctrl + L will degrade the shape further into an abstract, rounded blob.

Workflow Considerations

If your goal is to reduce file size or clean up complex geometry, geometric primitives rarely require simplification because they already consist of the minimum mathematical definitions required to render them. Applying Simplify to primitives is primarily useful when you intentionally want to distort, warp, or create organic variations out of rigid geometric outlines.
