How Inkscape Paint Bucket Computes Distance Fields

Inkscape’s Paint Bucket tool operates differently from standard vector path operations by using a hybrid raster-vector algorithm rather than direct geometric path clipping. To fill an area, the tool captures the current screen pixels, runs a flood fill to generate a binary mask, calculates a distance field across that mask to handle offset settings, and finally traces the result back into vector paths. This article explains the technical mechanics behind how Inkscape generates and computes this distance field to expand, contract, and refine fills.

Screen Space Rasterization and Mask Creation

When you activate the Paint Bucket tool, Inkscape does not compute mathematical intersections between SVG vector paths. Instead, it creates an offscreen raster buffer of the visible canvas at the current screen zoom level.

  1. Pixel Snapshot: The current viewport is rendered into an internal RGBA pixel array.
  2. Seed Fill: A flood fill algorithm begins at the coordinates of the click point, checking adjacent pixels against a threshold value determined by the tool settings (such as color, alpha, or channel differences).
  3. Binary Mask: The flood fill outputs a 1-bit binary raster mask where filled pixels are marked as 1 (foreground) and boundaries or non-matching pixels are marked as 0 (background).

Computing the Distance Field

To apply the "Grow/Shrink by" setting, Inkscape must compute an offset for the boundary of the filled region. Rather than applying a vector offset, Inkscape computes a Euclidean Distance Transform (EDT) directly on the binary bitmap mask.

The distance transform evaluates the distance from every pixel to the nearest edge of the binary mask:

  • Boundary Extraction: Inkscape identifies the perimeter pixels where 1 meets 0.
  • Metric Propagation: Using a two-pass linear-time Euclidean distance transform algorithm, Inkscape scans the pixel grid horizontally and vertically. For each pixel \((x, y)\), the algorithm calculates the minimum Euclidean distance: \[D(x, y) = \min_{(x', y') \in \text{Boundary}} \sqrt{(x - x')^2 + (y - y')^2}\]
  • Signed Field Representation:
    • For growing the fill, pixels outside the original fill region receive positive distance values indicating how far they are from the original shape.
    • For shrinking the fill, pixels inside the shape receive negative (or inverted) distance values indicating their depth relative to the exterior edge.

Because this computation runs in raster space over a bounded grid, the time complexity scales linearly with the number of pixels in the rendered viewport rather than the complexity of the underlying vector nodes.

Thresholding the Distance Field

Once the distance field is calculated across the buffer:

  1. The user-defined offset value (set in millimeters, pixels, or points) is converted into screen-pixel units based on the current zoom factor.
  2. A binary threshold is applied to the distance field. If the tool is set to grow by \(r\) pixels, every pixel with a distance \(D(x, y) \le r\) is marked as inside the new boundary. Conversely, if shrinking, pixels with an internal depth less than \(r\) are discarded.
  3. The result is an expanded or contracted binary bitmap that represents the modified target area with smoothed corners matching the Euclidean metric.

Vectorization via Potrace

Once the offset binary mask is finalized from the distance field, Inkscape converts the raster representation back into native SVG paths:

  1. Contour Extraction: Inkscape passes the modified binary bitmap to an embedded instance of the Potrace library.
  2. Path Fitting: Potrace extracts the boundary contours and decomposes them into a series of optimal Bézier curves and straight line segments.
  3. Coordinate Transformation: The resulting vector paths are transformed from screen-pixel coordinates back into standard SVG document space, accounting for document scale, viewbox, and viewport translation.
  4. Insertion: The generated <path> element is inserted into the active layer with the specified fill and stroke attributes.
