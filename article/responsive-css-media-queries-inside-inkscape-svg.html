Responsive CSS Media Queries Inside Inkscape SVG

This article outlines how to create responsive, self-contained SVG graphics by targeting elements exported from Inkscape using embedded CSS media queries. By assigning distinct classes and IDs in Inkscape, exporting clean SVG markup, and inserting a <style> block with viewport-specific rules directly into the XML, you can make an SVG change its layout, colors, or element visibility dynamically based on its display size.

1. Assign IDs and Classes in Inkscape

Before exporting, assign identifiable names and CSS classes to the shapes, paths, or groups you want to manipulate:

  1. Select the object or group on the canvas.
  2. Open the Object Properties panel (Shift + Ctrl + O).
  3. Set a unique ID (e.g., mobile-menu, desktop-banner).
  4. Set a Class name (e.g., hide-on-mobile, accent-fill).
  5. Click Set to apply the changes to the XML node.

Grouping related objects together (Ctrl + G) and assigning a class to the entire group simplifies toggling visibility later.

2. Export Clean SVG Markup

Inkscape includes proprietary metadata by default. To simplify manual editing:

  1. Go to File > Save As...
  2. Choose Optimized SVG (*.svg) or Plain SVG (*.svg) rather than "Inkscape SVG".
  3. If using "Optimized SVG", ensure that options which strip unused IDs or combine styles into presentation attributes do not remove the custom classes and IDs you assigned.

3. Adjust the Root SVG Element

Open the exported .svg file in a code editor. For responsive scaling to function properly:

  • Keep the viewBox attribute (e.g., viewBox="0 0 800 600").
  • Remove any hardcoded width and height attributes from the root <svg> tag, or set them to width="100%" and height="100%".

4. Insert Media Queries Inside the <style> Tag

Add a <style> element inside the <svg> tags (typically placed inside a <defs> block or immediately after the opening <svg> tag).

<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 800 600">
  <defs>
    <style>
      /* Base styles */
      .desktop-only {
        display: block;
      }
      .mobile-only {
        display: none;
      }
      .dynamic-shape {
        fill: #007acc;
      }

      /* Responsive rules based on SVG container width */
      @media (max-width: 480px) {
        .desktop-only {
          display: none;
        }
        .mobile-only {
          display: block;
        }
        .dynamic-shape {
          fill: #ff5722;
          transform: translateY(20px);
        }
      }
    </style>
  </defs>

  <!-- SVG Geometry from Inkscape -->
  <g class="desktop-only" id="desktop-details">
    <!-- Desktop-specific vector paths -->
  </g>
  <g class="mobile-only" id="mobile-simplified">
    <!-- Simplified mobile paths -->
  </g>
  <circle class="dynamic-shape" cx="400" cy="300" r="50" />
</svg>

5. Deployment Considerations

When CSS media queries are embedded inside an SVG, the query dimensions evaluate against the SVG's own viewport bounding box rather than the entire browser window. This effectively turns the SVG media queries into container queries.

To ensure the embedded media queries execute correctly in HTML:

  • Inline SVG: Pasting the raw <svg> code directly into HTML works seamlessly.
  • <object> Tag: Embedding via <object type="image/svg+xml" data="graphic.svg"></object> preserves the isolated document context and executes the media queries properly.
  • <img> Tag: Avoid using standard <img> tags if you rely on complex interactivity, though static CSS media queries are supported in modern browsers for isolated rendering.
