How Inkscape Calculates 3D Box Perspective Matrices

Inkscape’s 3D Box tool allows users to create pseudo-three-dimensional objects directly on a two-dimensional SVG canvas by mapping 3D coordinates to 2D space. To achieve this, Inkscape relies on projective geometry, using homogeneous coordinates and transformation matrices derived from user-defined vanishing points and an origin. This article explains the underlying mathematics, the structure of the projection matrix, and how Inkscape computes screen coordinates from 3D space.

The Mathematical Foundation: Projective Geometry

Inkscape models 3D space using projective geometry rather than standard Euclidean space. In standard 3D Euclidean space, parallel lines never intersect. In projective space (\(\mathbb{P}^3\)), parallel lines meet at an ideal point or "point at infinity."

When projected onto a 2D drawing surface (\(\mathbb{P}^2\)), these points at infinity can map to finite 2D coordinates known as vanishing points (VPs). Inkscape supports up to three vanishing points (one for each axis: \(X\), \(Y\), and \(Z\)), enabling one-point, two-point, and three-point perspective, as well as axonometric/isometric projections when vanishing points are set to infinity.

Homogeneous Coordinates

To project points from 3D space to a 2D canvas via matrix multiplication, Inkscape represents points using homogeneous coordinates:

  • A point in 3D projective space is represented as a 4-element column vector: \[\mathbf{P}_{3D} = \begin{bmatrix} X \\ Y \\ Z \\ W \end{bmatrix}\] For standard points, \(W = 1\). Direction vectors (points at infinity) have \(W = 0\).

  • The projected point on the 2D SVG canvas is represented as a 3-element column vector: \[\mathbf{p}_{2D} = \begin{bmatrix} x \\ y \\ w \end{bmatrix}\]

The final 2D Cartesian coordinates \((x_{svg}, y_{svg})\) on the canvas are calculated via perspective division: \[x_{svg} = \frac{x}{w}, \quad y_{svg} = \frac{y}{w}\]

Constructing the Projection Matrix

In Inkscape's source code (primarily implemented in persp3d.cpp and box3d.cpp), each 3D box references a perspective element (persp3d). This element defines:

  1. The canvas coordinates of the origin point \(O = (O_x, O_y)\).
  2. The vanishing points for the three principal axes: \(VP_x\), \(VP_y\), and \(VP_z\).

Inkscape maps the 3D unit basis vectors to their corresponding vanishing point directions on the canvas. The projection is performed using a \(3 \times 4\) transformation matrix \(\mathbf{M}\):

\[\mathbf{M} = \begin{bmatrix} m_{00} & m_{01} & m_{02} & m_{03} \\ m_{10} & m_{11} & m_{12} & m_{13} \\ m_{20} & m_{21} & m_{22} & m_{23} \end{bmatrix}\]

Each column of \(\mathbf{M}\) dictates where the standard 3D affine frame components map onto the 2D projective plane:

  • Column 0 (\(X\)-axis): Vector pointing toward \(VP_x\).
  • Column 1 (\(Y\)-axis): Vector pointing toward \(VP_y\).
  • Column 2 (\(Z\)-axis): Vector pointing toward \(VP_z\).
  • Column 3 (Origin): Projected position of \((0, 0, 0, 1)\), matching the chosen origin \(O\).

Handling Finite vs. Infinite Vanishing Points

The numerical contents of each axis column depend on whether that axis is set to a finite perspective or parallel (infinite) projection:

  1. Finite Vanishing Point: When an axis converges at a finite point \((V_x, V_y)\) on the canvas, the column introduces perspective foreshortening. The third row (\(m_{2j}\)) receives a non-zero value determined by the distance and focal scaling between the origin and the vanishing point. This ensures that as a coordinate value increases along that axis, the denominator \(w\) grows, compressing the geometry toward \((V_x, V_y)\).

  2. Infinite Vanishing Point (Parallel Lines): When an axis is set to parallel, its vanishing point is at infinity. The third row entry for that column (\(m_{2j}\)) is set to 0. Consequently, changing that coordinate does not affect the perspective divisor \(w\), producing affine/isometric lines that never converge.

The Transformation Pipeline

When rendering a 3D box, Inkscape computes the position of all eight corner vertices:

  1. Generate 3D Corner Coordinates: The box's local extent defines eight coordinates in the form \((X, Y, Z, 1)\) where each variable corresponds to a minimum or maximum bound of the box.
  2. Matrix Multiplication: Inkscape multiplies the projection matrix by each local vertex: \[\begin{bmatrix} x \\ y \\ w \end{bmatrix} = \mathbf{M} \begin{bmatrix} X \\ Y \\ Z \\ 1 \end{bmatrix}\]
  3. Perspective Divide: If \(w \neq 0\), the screen coordinates are extracted: \[x_{svg} = \frac{x}{w}, \quad y_{svg} = \frac{y}{w}\]
  4. SVG Path Generation: The resulting eight 2D points are ordered to form six quadrilateral faces. Inkscape generates standard SVG <path> elements for these faces, applying styling and sorting them by depth to ensure correct visual overlap.
