Inkscape Font Family Substitutions in Document XML

This article explains how Inkscape handles missing fonts within an SVG document's underlying XML structure. It details the exact elements and attributes where font references are maintained, clarifies why automatic substitutions are treated as non-destructive runtime operations rather than hardcoded XML tags, and identifies how Inkscape records text styling across document nodes.

Runtime Font Substitution vs. Document Storage

When an SVG containing fonts not installed on your operating system is opened, Inkscape relies on the system font engine (such as Pango and fontconfig) to pick a suitable fallback font visually.

Inkscape deliberately does not record automatic fallback substitutions as a permanent entry in the document XML. This non-destructive approach preserves the author's original typography intent so that the file will render accurately if transferred back to a system where the intended font is installed.

Location of Font Data in the XML Tree

All font declarations, whether currently available or missing, are stored within the SVG text hierarchy:

  1. Target Elements: Font metadata resides on <text> nodes or nested <tspan> elements.
  2. The style Attribute: Inkscape stores font declarations primarily inside inline CSS properties within the style attribute:
    • font-family: Contains the original, requested font family name (e.g., font-family:'Helvetica Neue', Arial, sans-serif;).
    • -inkscape-font-specification: A proprietary property generated by Inkscape to track the combined family, weight, and style chosen in the interface (e.g., -inkscape-font-specification:'Helvetica Neue, Normal').

When Font Substitutions Are Recorded

A font substitution is only committed to the document XML when a user explicitly alters the text or uses a replacement command:

  • Text and Font Dialog: Applying a replacement font updates the font-family and -inkscape-font-specification values inside the style attribute of the selected <text> or <tspan> element.
  • Document-Wide Replacements: If you resolve missing fonts using the "Replace Font" dialog or an extension, Inkscape rewrites the inline font-family string directly across all affected text elements in the XML source.

To inspect these values directly in Inkscape, open the XML Editor (Shift + Ctrl + X or Edit > XML Editor), navigate to any <svg:text> or <svg:tspan> tag, and review the style attribute in the attribute panel.
