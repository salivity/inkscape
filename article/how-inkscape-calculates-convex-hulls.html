How Inkscape Calculates Convex Hulls

This article explains how Inkscape determines the convex hull for a collection of vector objects, detailing the process of transforming arbitrary vector paths into discrete geometric points, applying coordinate transformations, and executing 2D convex hull algorithms using its underlying geometric engine, lib2geom.

Point Extraction from Vector Objects

Vector objects in Inkscape are primarily composed of cubic and quadratic Bézier curves, straight line segments, and basic geometric primitives (rectangles, circles, stars). Because a convex hull algorithm requires discrete coordinates rather than continuous mathematical equations, Inkscape first extracts representative boundary points from each object.

Due to the convex hull property of Bézier curves, any curve segment is strictly contained within the convex hull of its control points. Inkscape leverages this by gathering:

  • The endpoints (nodes) of all subpaths.
  • The off-curve control points (handles) of Bézier curves.
  • For tighter approximations where control cages would overestimate the boundary, points sampled at curve extrema (points of zero derivative along the X and Y axes) or points derived from adaptive path flattening.

Coordinate Space Normalization

When multiple vector objects or groups are selected, they often have independent transformation matrices (translations, rotations, shears, and scales). Before computing a unified boundary, Inkscape applies each object's accumulated transform matrix to its extracted points. This projects every coordinate into a common, global document coordinate space.

Algorithmic Computation via lib2geom

Inkscape delegates low-level geometric calculations to lib2geom, its dedicated computational geometry library. To compute the 2D convex hull of the aggregated point set, the library typically implements Andrew’s Monotone Chain algorithm (a variant of the Graham Scan):

  1. Sorting: The complete set of candidate points is sorted lexicographically, primarily by their X-coordinates and secondarily by their Y-coordinates.
  2. Hull Construction: The algorithm iterates through the sorted points to build two separate polygonal chains:
    • Lower Hull: Points are evaluated sequentially. If adding a new point causes a clockwise turn (determined using the sign of the 2D cross product of vectors between consecutive points), the preceding point is popped until a counterclockwise turn is restored.
    • Upper Hull: The process repeats in reverse order across the sorted list to build the upper boundary.
  3. Merging: The lower and upper chains are combined, omitting redundant endpoints, yielding an ordered polygon of vertices in \(O(N \log N)\) time complexity, where \(N\) is the total number of candidate points.

Generating the Resulting Path

Once the minimal bounding set of vertices is determined, Inkscape constructs a new closed SVG <path> element. The ordered vertices are joined with linear segments (L commands in SVG syntax), placed onto the active layer, and styled according to the active tool settings or default path parameters.
