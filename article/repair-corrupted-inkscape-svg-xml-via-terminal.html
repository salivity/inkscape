Repair Corrupted Inkscape SVG XML via Terminal

Inkscape drawings are saved in the Scalable Vector Graphics (SVG) format, an XML-based specification that requires strict syntactic structure. When an Inkscape file crashes during a save or suffers accidental corruption, invalid XML syntax can render the file unreadable by graphical editors. This guide covers the essential terminal tools available on Linux and macOS to diagnose, validate, and automatically reconstruct broken XML syntax in unreadable Inkscape files.

1. xmllint (libxml2)

xmllint is the standard command-line utility for parsing, validating, and formatting XML documents. It is typically included in the libxml2-utils (Debian/Ubuntu) or libxml2 (Fedora/macOS via Homebrew) packages.

Diagnosing the Error To pinpoint the exact line, column, and nature of the syntax failure without modifying the file, run:

xmllint --noout drawing.svg

The output will identify missing end-tags, unescaped entity references (such as naked & characters), or improper attribute encodings.

Repairing the File xmllint features a --recover flag that extracts as much valid XML as possible and generates closing tags for truncated elements:

xmllint --recover drawing.svg --output repaired_drawing.svg

This command ignores non-fatal parser errors, balances the document tree, and saves the output to a new file ready for Inkscape to open.

2. xmlstarlet

xmlstarlet is a lightweight XML toolkit that validates, queries, and transforms XML files directly from the shell.

Checking Well-Formedness Run the validation module to verify whether the drawing conforms to general XML rules:

xmlstarlet val -e drawing.svg

The -e flag instructs the tool to print detailed error messages rather than a generic failure status.

Reformatting and Recovery You can invoke the formatting engine with the recover flag to restore structural integrity:

xmlstarlet fo --recover drawing.svg > repaired_drawing.svg

This processes the document through an error-tolerant parser and outputs properly indented, valid XML.

3. tidy (HTML Tidy)

While originally built for HTML, tidy contains a robust XML mode capable of correcting mismatched tags, unclosed containers, and malformed entity declarations.

To parse and clean an Inkscape file, run:

tidy -xml -modify -wrap 0 drawing.svg
  • -xml: Forces the parser to apply strict XML processing instead of HTML rules.
  • -wrap 0: Prevents line-wrapping that could break long SVG path definitions (d="...").
  • -modify: Writes changes directly to the target file (create a backup copy before executing).

To write to a separate destination instead, use:

tidy -xml -wrap 0 -output repaired_drawing.svg drawing.svg

Manual Verification After Recovery

Automated recovery tools resolve syntax errors by closing tags prematurely or dropping malformed nodes, which can occasionally omit drawing layers. After generating a repaired file, check the document with:

xmllint --noout repaired_drawing.svg

If the command executes silently with an exit code of 0, the XML structure is completely valid and can be safely reopened in Inkscape.
