How to Export Strict SVG 1.1 in Inkscape

This guide outlines how to configure Inkscape to produce files that conform strictly to the W3C SVG 1.1 specification. By default, Inkscape saves documents as "Inkscape SVG," which introduces proprietary XML namespaces, editor metadata, and modern draft features that break strict SVG 1.1 validation. Following the steps below will ensure your exported files contain only standard SVG 1.1 elements, attributes, and formatting.

1. Avoid Features Outside the SVG 1.1 Specification

Before exporting, you must ensure the elements used in your document do not exceed SVG 1.1 standards:

  • Convert Flowed Text: SVG 1.1 does not support flowed text tags (<flowRoot>). Select any text created by clicking and dragging a bounding box, then navigate to Text > Convert to Text to change it into standard <text> elements with <tspan> tags. Alternatively, convert text entirely to outlines via Path > Object to Path.
  • Do Not Use Mesh Gradients: Mesh gradients are part of the SVG 2 proposal. Stick to standard linear and radial gradients.
  • Avoid CSS Mix-Blend-Modes: Advanced blend modes (other than standard SVG filters) are not supported in SVG 1.1. Stick to standard opacity or standard filter primitives if filter effects are required.

2. Configure Inkscape's SVG Output Preferences

Inkscape has internal preferences that dictate how SVG code is structured:

  1. Open Edit > Preferences (or press Ctrl + Shift + P).
  2. Navigate to Input/Output > SVG Output.
  3. Set Path data to use absolute or relative coordinates according to your preference, but ensure numeric precision is set reasonably (typically 4–8 digits).
  4. Set Style sheet handling: Under Formatting, adjust attributes to save styles as presentation attributes (e.g., fill="...") rather than inline CSS (style="fill:...") if your target SVG 1.1 parser prefers attribute-based styling.

3. Clean Document Definitions

Unused definitions can retain non-compliant metadata and IDs. Clear them before export:

  1. Go to File > Clean Up Document to remove unused gradients, patterns, and markers.
  2. Open File > Document Properties and ensure the page dimensions are explicitly defined without custom vendor view properties.

4. Export as Optimized SVG

The best way to guarantee a strict SVG 1.1 file is using the Optimized SVG exporter, which uses the Scour engine to strip proprietary namespaces and non-standard syntax:

  1. Click File > Save As... (or Ctrl + Shift + S).
  2. In the file type dropdown, select Optimized SVG (*.svg).
  3. In the export dialog that appears, configure the tabs as follows:
    • Options Tab:
      • Check Remove unused IDs.
      • Check Shorten ID values.
      • Check Convert styles to XML attributes (SVG 1.1 handles presentation attributes reliably).
      • Check Remove inkscape:/ and sodipodi:/ attributes**.
    • SVG Metadata Tab:
      • Check Remove metadata (removes RDF/Dublin Core metadata that may cause strict parsers to fail).
      • Check Remove unneeded whitespace.
    • Output Format Tab:
      • Uncheck Create XML declaration (optional, but prevents XML parsing conflicts on some strict SVG engines).
      • Set Number of significant digits for coordinates (4 is typically optimal).
  4. Click OK to save the compliant file.
