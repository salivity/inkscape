Why Inkscape Flowed Text Fails in Web Browsers

Flowed text created in Inkscape often fails to render in web browsers because it relies on an abandoned SVG 1.2 draft specification that modern browser rendering engines do not support. When users click and drag a text box in Inkscape, the software historically generated proprietary <flowRoot> elements rather than standard SVG text elements. This article explains the technical reasons behind this rendering failure and provides direct solutions to make your SVG text visible across all standard web browsers.

The Cause: The Abandoned SVG 1.2 Draft

The issue originates from an inconsistency between SVG standards and browser adoption:

  1. The Introduction of <flowRoot>: In older versions of Inkscape (and certain legacy templates), dragging a bounding box to create text generates an experimental SVG 1.2 structure using <flowRoot>, <flowRegion>, and <flowPara> elements.
  2. Standard Abandonment: The World Wide Web Consortium (W3C) never finalized the SVG 1.2 Full specification. As a result, major browser engines (Blink, Gecko, and WebKit) never implemented native support for the <flowRoot> tag.
  3. Browser Fallback: Because browsers strictly implement SVG 1.1 and finalized parts of SVG 2, any element they do not recognize is ignored. Browsers parse the file, encounter <flowRoot>, fail to recognize how to position or render it, and simply display a blank area where the text should be.

How Flowed Text Is Accidentally Created

In Inkscape, text is inserted in one of two ways:

  • Regular Text: Selecting the Text tool and clicking once on the canvas. This creates a standard, fully supported SVG <text> element.
  • Flowed Text: Selecting the Text tool and clicking and dragging to define a boundary box. This creates the unsupported <flowRoot> structure.

How to Fix Flowed Text for Web Compatibility

To ensure text renders properly across all browsers, you must convert flowed text into a standard format before exporting.

Method 1: Convert to Regular Text (Recommended)

This method preserves the text as live, selectable, and searchable text while removing the unsupported bounding box elements.

  1. Select the affected text object on the canvas.
  2. Go to the top menu and select Text.
  3. Click Convert to Text.

Inkscape will convert the <flowRoot> into standard SVG <text> elements containing <tspan> tags. Note that automatic line wrapping will be lost, so manual line breaks may be required.

Method 2: Convert Text to Paths

If preserving the visual layout and exact line breaks is more critical than maintaining selectable text, convert the text into vector outlines.

  1. Select the text object.
  2. Go to the top menu and select Path.
  3. Click Object to Path (or press Ctrl + Shift + C / Cmd + Shift + C).

This replaces the font elements with standard vector shapes (<path>). The visual appearance will remain identical in every browser, though the text will no longer be editable or selectable.

Method 3: Use SVG 2 Text Auto-Wrapping in Recent Versions

Recent releases of Inkscape (version 1.0 and newer) support standard SVG 2 text auto-wrapping using CSS inline-size. If you are using an updated version of Inkscape:

  1. Ensure your file is saved as Plain SVG or Optimized SVG rather than Inkscape SVG.
  2. Verify that older <flowRoot> elements are migrated by selecting Text > Convert to Text and re-applying wrapping using the updated text tool settings compatible with SVG 2.
