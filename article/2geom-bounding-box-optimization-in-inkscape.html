2Geom Bounding Box Optimization in Inkscape

During interactive vector editing in Inkscape, the 2Geom computational geometry library provides real-time bounding box recalculations by replacing expensive numerical sampling with analytical polynomial root-finding, hierarchical cache invalidation, and conservative convex hull approximations. By isolating path segment extrema mathematically and deferring calculations until necessary, 2Geom ensures that operations such as node dragging, live path transformations, and viewport rendering remain responsive even across complex vector paths.

Analytical Extrema Finding

Instead of approximating Bézier curves through iterative subdivision or point-sampling (flattening), 2Geom calculates the exact mathematical extrema of parametric curves. For a cubic Bézier curve, the coordinate functions \(X(t)\) and \(Y(t)\) are degree-3 polynomials. 2Geom computes the first derivative of these functions:

\[X'(t) = 0 \quad \text{and} \quad Y'(t) = 0\]

Because the derivative is a quadratic equation, its roots can be solved analytically using the quadratic formula in constant time (\(O(1)\)). 2Geom checks for real roots within the valid parameter interval \(t \in [0, 1]\). The exact geometric bounding box is then determined simply by evaluating the curve at \(t = 0\), \(t = 1\), and any valid stationary points. This eliminates unnecessary floating-point operations and guarantees mathematically tight bounds instantly.

Conservative Hull Approximation and Fast Rejection

When an interactive edit begins—such as moving an object or testing for mouse hovering—calculating exact bounds for every path segment can still become costly. 2Geom optimizes this by utilizing the convex hull property of Bézier curves: any Bézier curve is strictly contained within the convex hull of its control points.

Computing the minimum and maximum coordinates of the control polygon requires only simple comparisons. 2Geom uses this coarse, conservative bounding box for rapid intersection tests, snapping calculations, and spatial queries. If the conservative bounding box does not intersect a target region or cursor position, the engine discards the segment immediately without solving the polynomial derivatives.

Distinguishing Geometric and Visual Bounds

2Geom separates calculations into geometric bounding boxes (the mathematical stroke path) and visual bounding boxes (which account for stroke width, miters, line caps, and markers):

  • Geometric Bounds: Evaluated directly via the curve functions.
  • Affine Transformations: When an entire path or group is translated, scaled, or rotated, 2Geom does not recalculate the curve roots from scratch. Instead, it applies the transformation matrix directly to existing coordinate bounds where possible, or updates the transformed polynomial coefficients directly before root finding.
  • Visual Expansions: Stroke expansion is treated as an offset operation. Rather than computing offset curves—which are mathematically non-polynomial and computationally heavy—2Geom conservatively inflates the geometric bounding box by half the stroke width, adjusting specifically for miter limits and join styles only when tight redraws are required.

Hierarchical Invalidation and Lazy Evaluation

Inkscape arranges visual elements in a Document Object Model (DOM) tree. 2Geom supports this structure through hierarchical bounding boxes:

  1. Local Node Caching: Each path segment and grouped object stores a cached bounding box.
  2. Selective Invalidation: When a user manipulates a single node, 2Geom marks only that modified segment and its immediate parent nodes as "dirty." Untouched segments within the same path retain their cached bounds.
  3. Lazy Evaluation: Bounding boxes are not recalculated continuously on every micro-motion of the cursor. Recalculation is deferred until an external system—such as the canvas redraw cycle, the snapping engine, or the selection tool UI—explicitly queries the box.
  4. Bottom-Up Aggregation: When queried, the engine calculates the bounds of dirty leaf nodes and unions them up the tree, minimizing overall traversal time.
