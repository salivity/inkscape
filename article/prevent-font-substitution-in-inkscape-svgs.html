Prevent Font Substitution in Inkscape SVGs

Font substitution occurs in Inkscape when an SVG file references typography that is not installed on your local operating system, causing the software to fall back to a default system font. This article covers why this happens and provides actionable methods to prevent or resolve font mismatches, including converting text to paths, embedding web fonts directly into the SVG, installing the required typefaces, and utilizing Inkscape's built-in font mapping tools.

Why Font Substitution Occurs

Standard SVG files store text elements as live, editable strings paired with CSS font-family declarations rather than raw vector shapes. When Inkscape opens an SVG file created on another machine, it queries your operating system's font registry for the specified font family. If that font is absent, Inkscape substitutes it with a fallback font (typically a generic sans-serif or serif typeface), altering the document's kerning, line heights, and overall visual layout.

1. Convert Text to Paths (Best for Static Graphics)

If the text within the SVG does not need to be edited later, the most reliable way to guarantee identical rendering across all devices is to convert the text to vector outlines before exporting or sharing the file.

  1. Select the text object(s) in Inkscape.
  2. Navigate to the top menu and select Path > Object to Path (or press Shift + Ctrl + C).
  3. Save the file.

Note: Once converted to paths, the text behaves as vector nodes and can no longer be edited using the Text tool. Always retain a backup copy with live text for future revisions.

2. Install the Required Fonts Locally

When you need to keep text fully editable, installing the missing font family on your computer resolves substitution issues instantly.

  1. Identify the missing font by selecting the substituted text and opening the Text and Font panel (Text > Text and Font or Shift + Ctrl + T). Missing fonts typically display with a warning icon or strike-through.
  2. Obtain the appropriate font files (.ttf or .otf) from a legitimate font provider or the original file creator.
  3. Install the font on your operating system (right-click the font file and select Install).
  4. Restart Inkscape and reopen the SVG file.

3. Embed Fonts Directly into the SVG Code

For web-based or portable workflows where text must remain selectable or screen-reader accessible without requiring local font installation, you can embed the font data directly inside the SVG using Base64 encoding.

  1. Convert your font file (.woff or .ttf) into a Base64 string using an online font converter.
  2. Open the SVG in Inkscape and launch the XML Editor (Edit > XML Editor or Shift + Ctrl + X).
  3. Add a <style> element inside the <defs> section containing a @font-face rule:
<defs>
  <style type="text/css">
    @font-face {
      font-family: 'YourFontName';
      src: url('data:font/woff2;charset=utf-8;base64,BASE64_DATA_HERE') format('woff2');
    }
  </style>
</defs>
  1. Ensure your text objects reference the same font-family name in their styling.

4. Map Fallback Fonts in Inkscape

If you cannot install the original font or modify the source file, manually assign a suitable replacement that closely matches the metrics of the missing font.

  1. Open the document in Inkscape.
  2. Open the Text and Font dialog (Shift + Ctrl + T).
  3. Select the text element displaying the substituted font.
  4. Choose a compatible, installed typeface from the font list and click Apply.
  5. Adjust the font size and letter spacing in the tool controls bar to preserve the original layout alignment.
