Intersecting Cubic Bezier Curves in Inkscape

Calculating the exact intersection points of two overlapping cubic Bézier curves is a fundamental challenge in vector graphics. Inkscape solves this using its underlying computational geometry engine, lib2geom, which avoids fragile pure-algebraic methods in favor of a robust hybrid numerical pipeline. This article breaks down how Inkscape handles curve intersection through hierarchical bounding box rejection, Bézier clipping via de Casteljau subdivision, and multi-dimensional Newton-Raphson root refinement to achieve floating-point precision.

The Underlying Mathematical Challenge

A cubic Bézier curve is defined parametrically by four control points:

\[C(t) = (1-t)^3 P_0 + 3(1-t)^2 t P_1 + 3(1-t) t^2 P_2 + t^3 P_3 \quad \text{for } t \in [0, 1]\]

Finding where two curves, \(C_1(u)\) and \(C_2(v)\), intersect means solving for parameter values \((u, v)\) such that:

\[C_1(u) - C_2(v) = 0\]

Analytically converting one parametric cubic into an implicit algebraic equation (\(F(x, y) = 0\)) produces a polynomial of degree 3. Substituting the parametric equations of the second curve into this implicit equation yields a single univariate polynomial of degree \(3 \times 3 = 9\). Solving a 9th-degree polynomial algebraically is analytically impossible via radicals and computationally unstable due to numerical precision loss and catastrophic cancellation. Consequently, Inkscape relies on geometric and numerical algorithms.

The Core Engine: lib2geom

Inkscape delegates geometric computations to lib2geom, an open-source C++ geometry library designed specifically for vector graphic manipulation. Lib2geom implements a three-stage pipeline to compute intersections:

  1. Bounding Box and Convex Hull Pruning
  2. Bézier Clipping and Domain Subdivision
  3. Local Numerical Refinement

Step 1: Spatial Partitioning and Convex Hull Culling

Before performing deep mathematical operations, lib2geom rapidly eliminates curve segments that cannot possibly intersect.

Bézier curves possess the convex hull property, which states that the entire curve lies strictly within the convex polygon formed by its four control points. Inkscape uses this property in stages:

  1. Axis-Aligned Bounding Boxes (AABB): Quick interval checks determine if the overall bounding boxes overlap. If they do not, the curves cannot intersect, and the check aborts immediately.
  2. Convex Hull Intersection Tests: If the AABBs overlap, the library tests the tighter convex hulls using the Separating Axis Theorem (SAT). If a separating line exists between the two convex hulls, calculation ends.

Step 2: Bézier Clipping and de Casteljau Subdivision

When bounding regions overlap, lib2geom uses a technique known as Bézier Clipping (originally introduced by Sederberg and Nishita) combined with de Casteljau’s subdivision algorithm.

  1. Defining the Distance Function: A baseline is constructed between the endpoints of the first curve, \(C_1(0)\) and \(C_1(1)\). The second curve, \(C_2\), is projected into a 1D coordinate frame measuring perpendicular distance from this line.
  2. Interval Reduction: Because this distance function is also a cubic polynomial, its convex hull can be mapped against the zero-distance line. The points where this hull crosses zero define a reduced parameter range \([v_{\min}, v_{\max}]\) outside of which no intersection can exist.
  3. Subdivision: If the parameter interval cannot be cleanly reduced by clipping alone, Inkscape splits the curve into two halves using de Casteljau's algorithm at \(t = 0.5\). This creates a tree of sub-curves, each tested recursively until the segment lengths drop below a predefined tolerance threshold.

Step 3: Newton-Raphson Polish to Exact Precision

Once subdivision isolates a candidate intersection into an extremely tight parameter window, Inkscape switches to a local bivariate Newton-Raphson iteration to reach full machine precision:

\[\mathbf{F}(u, v) = C_1(u) - C_2(v) = \begin{bmatrix} X_1(u) - X_2(v) \\ Y_1(u) - Y_2(v) \end{bmatrix} = \mathbf{0}\]

Starting from the midpoint of the subdivided interval \((u_0, v_0)\), the algorithm updates the estimates iteratively:

\[\begin{bmatrix} u_{k+1} \\ v_{k+1} \end{bmatrix} = \begin{bmatrix} u_k \\ v_k \end{bmatrix} - J^{-1} \mathbf{F}(u_k, v_k)\]

where \(J\) is the Jacobian matrix of first-order derivatives:

\[J = \begin{bmatrix} X'_1(u) & -X'_2(v) \\ Y'_1(u) & -Y'_2(v) \end{bmatrix}\]

Because the derivatives of cubic Bézier curves are easily calculated quadratic Bézier curves, each iteration executes rapidly and exhibits quadratic convergence, resolving the exact coordinates within 3 to 5 iterations.

Handling Degenerate Cases

Inkscape’s engine includes explicit handlers for edge cases:

  • Tangential Contacts: When curves touch without crossing, the Jacobian determinant approaches zero. Lib2geom detects this condition and solves the roots by examining higher-order derivatives or checking sign changes across the local curvature.
  • Overlapping Segments (Infinite Intersections): If two curves share an entire arc, subdivision would theoretically recurse infinitely. Inkscape detects collinear control points and identical parameterizations early, collapsing the infinite set into the segment's bounding endpoints.
