Inspect SVG Font Licensing Metadata in Inkscape

This guide demonstrates how to locate and inspect font licensing metadata embedded inside an imported Scalable Vector Graphics (SVG) document using Inkscape. SVG files often contain font references, embedded SVG fonts, or embedded Base64-encoded web fonts, which typically include copyright notices, license URLs, and usage restrictions. By utilizing Inkscape’s XML Editor and Document Metadata tools, you can examine these underlying declarations to ensure compliance with font usage terms.

1. Check Document-Level Licensing Metadata

When fonts or assets are authored and exported into an SVG, licensing information is frequently placed into the document’s global Dublin Core metadata block.

  1. Open your SVG file in Inkscape (File > Open...).
  2. Go to File > Document Properties... (or press Ctrl + Shift + D / Cmd + Shift + D).
  3. Click on the Metadata tab.
  4. Review the fields:
    • Rights / License: Lists specific licenses (such as SIL Open Font License, Creative Commons, or proprietary commercial agreements).
    • Creator / Publisher: Names the font foundry, designer, or software that generated the file.
    • Description: Often stores inline EULA summaries or font attribution notices.

2. Inspect Font Nodes and CSS via the XML Editor

Most technical font metadata, especially for embedded SVG fonts or embedded web fonts, is stored directly inside the XML tree.

  1. Open the XML Editor by navigating to Edit > XML Editor... (or press Ctrl + Shift + X / Cmd + Shift + X).
  2. Expand the root <svg:svg> node.
  3. Locate and expand the <svg:defs> element. Font data and styling are typically held here:
    • <svg:font> or <svg:font-face> elements: Expand these nodes. Select <svg:font-face> and look at the attributes in the right-hand panel. Attribute values like font-family, unicode-range, or custom vendor attributes often carry versioning and copyright markers. Check child nodes for <svg:metadata> or <svg:description>.
    • <svg:style> elements: If the font is embedded via CSS (@font-face), select the <svg:style> node. In the right panel, inspect the CSS text. Font creators frequently include commented license headers immediately preceding @font-face { ... } or within the base declaration.

3. Review Dublin Core Metadata Nodes in XML

If the Document Properties dialog does not show license details, raw metadata tags may still exist in the XML structure:

  1. In the XML Editor, expand the <svg:metadata> node.
  2. Expand <rdf:RDF> followed by <cc:Work> or <rdf:Description>.
  3. Look for explicit licensing elements:
    • <dc:rights>: Holds direct copyright statements.
    • <cc:license rdf:resource="..." />: Points to the official URL of the license governing the file and embedded assets.
    • <dc:relation>: Sometimes links directly to the original font repository or EULA page.

4. Handling Base64-Embedded Fonts

If the SVG embeds font binaries directly using data:application/font-woff;base64,... or data:font/ttf;base64,... within an embedded stylesheet:

  1. Locate the <svg:style> node inside the XML Editor.
  2. Highlight the raw text containing the Base64 string.
  3. Check the plain text comments immediately above or below the Base64 block, where font export tools typically inject attribution and license notices.
  4. If no text comment exists, the license table resides inside the binary font data itself (the name table of OpenType/TrueType data), requiring the Base64 string to be extracted and analyzed with a specialized font inspection tool outside Inkscape.

Important Caveat: Outlined Text

If the text in the SVG was converted to paths (represented as <svg:path> elements rather than <svg:text>), the original font software has been removed from the file. Path-based text retains no embedded font licensing tables, metadata, or font software restrictions, though the artwork itself remains subject to the overall vector illustration's copyright.
